### Full width

A button is as wide as its label and takes its parent's alignment. Add `w-full` to fill the space. A parent's `items-stretch` or `self-stretch` won't widen it. To go back to the label's width at a breakpoint, use `w-fit`, not `w-auto`.

```tsx-live
<div className='grid max-w-sm gap-2'>
  <Button emphasis='strong' className='w-full'>Checkout</Button>
  <Button className='w-full sm:w-fit'>Keep browsing</Button>
</div>
```

### Pending

Set `pending` while the button's action is under way. It stops responding to clicks and keys, keeps focus and its place in the tab order, and stays the same size. After 200ms its label fades and a spinner in the label's colour takes its place, so a fast response never flashes a loader. A pending submit button doesn't submit its form, even from `Enter` in a field. `disabled` wins over `pending`.

```tsx-live layout=row
<Button emphasis='strong' pending>Strong</Button>
<Button emphasis='normal' pending>Normal</Button>
<Button emphasis='subtle' pending>Subtle</Button>
<Button emphasis='subtler' pending>Subtler</Button>
<IconButton aria-label='Refresh' pending>
  <ArrowClockwiseIcon weight='bold' />
</IconButton>
```

Hold it for as long as the work takes, then show the result: a toast, the field's error, or the next page.

```tsx-live-noinline
function SendTickets() {
  const [pending, setPending] = useState(false)
  return (
    <form
      className='grid max-w-sm gap-3'
      onSubmit={(event) => {
        event.preventDefault()
        setPending(true)
        setTimeout(() => setPending(false), 2000)
      }}
    >
      <Field>
        <Field.Label>Email</Field.Label>
        <Field.Input type='email' defaultValue='sam@example.com' />
      </Field>
      <Button type='submit' emphasis='strong' intent='accent' pending={pending}>
        Send tickets
      </Button>
    </form>
  )
}
render(<SendTickets />)
```

The look comes from `aria-busy='true'` on any element with the `btn` class, so markup that isn't React, such as the deprecated `LinkButton` or a link in a Vue widget, gets it from the attribute. The element's behaviour is then yours: pair it with `aria-disabled='true'` and stop the click.

### Href

Pass `href` to render the button as a routed anchor. Roadie picks the right element + safety attributes based on the href shape: internal routes go through your configured [`RoadieLinkProvider`](/foundations/linking); external hrefs (`https://…`, `//…`) auto-render with `target='_blank' rel='noopener noreferrer'`; protocol hrefs (`mailto:` / `tel:` / `sms:`) render plain anchors.

```tsx-live layout=row gap=4
{/* Internal */}
<Button href='/foundations/linking' emphasis='strong' intent='accent'>
  Read about linking
</Button>
{/* External */}
<Button href='https://oztix.com.au' emphasis='normal'>
  Open Oztix
  <ArrowSquareOutIcon weight='bold' className='size-4' />
</Button>
{/* Protocol */}
<Button href='mailto:hello@oztix.com.au' emphasis='subtle'>
  <EnvelopeIcon weight='bold' className='size-4' />
  Email us
</Button>
```

Hover each button. The browser status bar shows the resolved `href` exactly as Roadie rendered it. See [Linking](/foundations/linking) for the full reference: provider setup, the external/internal/protocol decision tree, and the `external`/`target`/`rel` overrides.

### Download

Add `download` to an `href` button to save the file instead of opening it, optionally under a filename. A file isn't a route, so the button renders a plain `<a>` and skips the provider's Link, which would otherwise prefetch the file as a page. That also means it gets no base path: if your app has one, add it to the `href` yourself.

```tsx-live
<Button href='/roadie-logo.png' download='roadie-logo.png'>
  <DownloadIcon weight='bold' className='size-4' />
  Download logo
</Button>
```

### Escape hatch

For full element control, or anchor props `href` doesn't cover (`hreflang`, `referrerPolicy`), use Base UI's `render` prop. It keeps Base UI's button semantics, which are `role='button'` and `Space` activation. The element you pass is yours to make accessible. Passing both `href` and `render` triggers a one-shot dev warning. `render` wins, and provider routing is silently disabled.

## Guidelines

Write labels with [Interface copy](/content/interface-copy#buttons).

Use `pending` for an action that is slow or can't be undone, such as a payment or a send. For a fast one that can be undone, update the screen at once and reconcile in the background instead ([Interactions](/foundations/interactions#feedback-and-state)). Keep the label: the spinner says it's working, and the label is still what a screen reader names.

## Accessibility

- **Keyboard**: `Enter` or `Space` activates the button. With `href` it is a link, so `Enter` follows it and `Space` scrolls the page. Focus is indicated by a semi-transparent ring via `is-interactive`.
- **ARIA**: Renders a native `<button>`, or an `<a>` with `href`. A disabled link gets `aria-disabled`, leaves the tab order and doesn't navigate.
- **Pending**: Sets `aria-busy` and `aria-disabled` and keeps focus, so a keyboard submit doesn't drop focus to the page. The label stays the button's name. The button doesn't announce the wait itself; announce the result instead, with a toast or `Field.ErrorText`.
- **IconButton**: Requires an `aria-label` prop (enforced by TypeScript) since there is no visible text.
