A month or week grid for choosing a date, several dates or a range.

## Import

```tsx
import { Calendar } from '@oztix/roadie-components/calendar'
```

## Examples

### Default

Calendar opens on the selected month, or on today's. Every value is a plain ISO date string such as `'2026-11-27'`, never a `Date`. Today moves on at midnight in `timeZone`. Server HTML may be read on a later day, so the server leaves today unmarked, and a calendar with nothing else to place its month renders an empty six-week frame until the browser fills it in. Pass `today`, `month`, `defaultMonth` or a selection to render it in full on the server.

The month's name sits at the start of the header and both arrows sit at the end. On a touch screen, swipe the days sideways to turn the month. The days follow the finger, or turn straight away when the reader prefers reduced motion, and the swipe runs the other way in a right-to-left page.

```tsx-live-noinline
function Default() {
  const [date, setDate] = useState(null)
  return (
    <div className='grid gap-4'>
      <Calendar selected={date} onSelect={setDate} />
      <p className='text-sm text-subtle'>Selected: {date ?? 'none'}</p>
    </div>
  )
}

render(<Default />)
```

### Variants

`captionLayout='dropdown'` swaps the month name for month and year selects, for dates far from today such as a date of birth. `startMonth` and `endMonth` limit how far either way they reach.

```tsx-live
<Calendar
  captionLayout='dropdown'
  defaultMonth='1990-06-01'
  startMonth='1920-01-01'
  endMonth='2010-12-31'
/>
```

### With a range

`mode='range'` takes `{ start, end }`. The first press sets `start` and leaves `end` null, and the days between preview as the pointer or focus moves. `min` and `max` limit the length in days, both ends counted. Days that would break them dim. Pressing one keeps the start and announces the rule, such as "Ranges can be up to 14 days", so say the rule in visible text near the calendar too. Pressing the start again makes a one-day range, or drops the start when `min` is more than 1, and `Escape` drops it. For a range in a form or a toolbar, with presets and typed dates, use [DateRangePicker](/components/date-range-picker).

```tsx-live-noinline
function Range() {
  const [range, setRange] = useState({ start: null, end: null })
  return (
    <div className='grid gap-4'>
      <p className='text-sm text-subtle'>Choose up to 14 days.</p>
      <Calendar mode='range' max={14} selected={range} onSelect={setRange} />
      <p className='text-sm text-subtle'>
        {range.start ?? '…'} to {range.end ?? '…'}
      </p>
    </div>
  )
}

render(<Range />)
```

### With several dates

`mode='multiple'` takes a list of dates and keeps it in order.

```tsx-live
<Calendar
  mode='multiple'
  defaultMonth='2026-11-01'
  defaultSelected={['2026-11-06', '2026-11-13', '2026-11-20']}
/>
```

### With past dates disabled

`disabled` takes matchers: a date, a list of dates, `{ start, end }`, `{ before }`, `{ after }`, `{ dayOfWeek }` with 1 for Monday, or a function of the date. Disabled days can still be focused, so keyboard users can move past them.

```tsx-live-noinline
const today = plainDateOf(new Date(), viewerTimeZone())

render(<Calendar disabled={{ before: today }} showOutsideDays />)
```

### With modifiers

`modifiers` names sets of days with the same matchers. Each name becomes a data attribute on its days, so `hasSession` renders `data-has-session` to style. Here Lampshade Disco at Kazoo Hollow Room runs on the bold nights, and the struck-through night is sold out.

```tsx-live-noinline
const sessions = ['2026-11-05', '2026-11-06', '2026-11-07', '2026-11-12', '2026-11-13', '2026-11-14']
const soldOut = ['2026-11-07']

render(
  <div className='grid gap-4'>
    <Calendar
      defaultMonth='2026-11-01'
      modifiers={{ hasSession: sessions, soldOut }}
      disabled={[(date) => !sessions.includes(date), ...soldOut]}
      className='**:data-has-session:font-bold **:data-sold-out:line-through'
    />
    <p className='text-sm text-subtle'>Bold nights have a show. Struck-through nights are sold out.</p>
  </div>
)
```

### With two months

`numberOfMonths` shows months side by side where they fit and stacks them where they don't. Both arrows sit together at the top end, and each moves the set one month.

```tsx-live
<Calendar mode='range' numberOfMonths={2} />
```

### With scrolling months

`layout='scroll'` stacks the months in a list that scrolls, as on a phone, under one row of weekdays that stays pinned. There are no arrows: it opens on `month`, the selection or today, and adds months as it nears either end or the keyboard moves past them. A new `month` scrolls the list to it, and in a box that scrolls `onMonthChange` reports the month at the top as it scrolls. Put it in a box that scrolls. To run the pinned row to the box's edges, pad the calendar and pull its `calendar-weekdays` slot out by the same amount, as here. Pickers use it in their phone drawer.

```tsx-live
<div className='h-96 overflow-y-auto rounded-xl emphasis-raised'>
  <Calendar
    layout='scroll'
    mode='range'
    defaultSelected={{ start: '2026-11-06', end: '2026-11-12' }}
    className='px-4 **:data-[slot=calendar-weekdays]:-mx-4 **:data-[slot=calendar-weekdays]:px-4'
  />
</div>
```

### With vertical paging

`direction='vertical'` turns the months up and down: the arrows point up and down, and a finger swipes up for the next month. Over the days, a finger no longer scrolls the page up and down, so use it only where the calendar has the screen to itself. For one continuous list of months, use `layout='scroll'` instead.

```tsx-live
<Calendar direction='vertical' defaultMonth='2026-11-01' />
```

### With a week view

`view='week'` shows one week as a row of larger days, and the arrows and a swipe turn a week at a time. It suits choosing a session in the coming days. `views` lists the views the reader can switch between. With both, a "Month view" toggle sits beside the title. Use `defaultView` to open on one, or `view` and `onViewChange` to control it.

```tsx-live-noinline
function Week() {
  const [date, setDate] = useState(null)
  return (
    <div className='grid gap-4'>
      <Calendar
        defaultView='week'
        views={['week', 'month']}
        defaultMonth='2026-11-01'
        selected={date}
        onSelect={setDate}
      />
      <p className='text-sm text-subtle'>Selected: {date ?? 'none'}</p>
    </div>
  )
}

render(<Week />)
```

### With day content

`getDayContent` adds content under a day's number, such as a price or how many sessions are left, in the month and the week alike. Return null for a plain day, not an empty element. Every day becomes a tile so the columns line up, days with content are filled, and tiles grow to fit, so a long line wraps rather than spills. Tiles stay up to 64px wide, or 80px in a week. A disabled day with content is struck through, so here sold-out nights read as unavailable while nights outside the run stay plain. The content describes the day to screen readers, so give a mark like a dot some words too.

```tsx-live-noinline
const nights = {
  '2026-10-28': { price: 29, left: 2 },
  '2026-10-29': { price: 29, left: 4 },
  '2026-10-30': { soldOut: true },
  '2026-10-31': { price: 35, left: 1 },
  '2026-11-01': { price: 35, left: 3 },
  '2026-11-04': { price: 29, left: 4 },
  '2026-11-05': { price: 29, left: 2 },
  '2026-11-06': { price: 35, left: 1 },
  '2026-11-07': { soldOut: true },
  '2026-11-08': { price: 35, left: 4 },
  '2026-11-11': { price: 29, left: 4 },
  '2026-11-12': { price: 29, left: 3 },
  '2026-11-13': { price: 39, left: 4 },
  '2026-11-14': { price: 39, left: 4 },
  '2026-11-15': { price: 39, left: 2 }
}

function nightContent(date) {
  const night = nights[date]
  if (!night) return null
  if (night.soldOut) return 'Sold out'
  return (
    <>
      <span>${night.price}</span>
      <span aria-hidden='true' className='flex gap-0.5'>
        {Array.from({ length: night.left }, (_, i) => (
          <span key={i} className='size-1 rounded-full bg-current' />
        ))}
      </span>
      <span className='sr-only'>
        {night.left === 1 ? '1 session left' : `${night.left} sessions left`}
      </span>
    </>
  )
}

function Sessions() {
  const [date, setDate] = useState(null)
  return (
    <div className='grid max-w-md gap-4'>
      <Calendar
        views={['week', 'month']}
        defaultMonth='2026-11-01'
        selected={date}
        onSelect={setDate}
        disabled={(date) => !nights[date] || nights[date].soldOut}
        getDayContent={nightContent}
      />
      <p className='text-sm text-subtle'>
        Ember Galah Ball at Kazoo Hollow Room. Dots show sessions left.
      </p>
    </div>
  )
}

render(<Sessions />)
```

## Guidelines

- **It fills its container.** The seven columns share the width, each day stays a circle up to 48px across, or a tile up to 64px with `getDayContent`, in the middle of its column, and a range's band runs from edge to edge. In a popover, it takes 280px a month. Set the width on the container, not the calendar.

<div className='grid gap-8'>

<Guideline title='Pass plain dates'>
  <Guideline.Do code={`<Calendar selected='2026-11-27' />`}>
    Pass ISO date strings. A plain date names the same day in every time zone.
  </Guideline.Do>
  <Guideline.Dont code={`<Calendar selected={new Date('2026-11-27')} />`}>
    Don't pass a <code>Date</code>. It is an instant, so it can land on the day before or after in another zone.
  </Guideline.Dont>
</Guideline>

<Guideline title='Disable days, rather than hide them'>
  <Guideline.Do code={`<Calendar disabled={{ before: today }} />`}>
    Disable days that can't be chosen, so the grid keeps its shape and keyboard users can move past them.
  </Guideline.Do>
  <Guideline.Dont>
    Don't style a day to look unavailable without disabling it. It still selects.
  </Guideline.Dont>
</Guideline>

<Guideline title='Give day content words'>
  <Guideline.Do>
    Pair a mark, such as a dot for each session left, with hidden text like "2 sessions left". The content describes the day to screen readers.
  </Guideline.Do>
  <Guideline.Dont>
    Don't put content in every day to make the calendar look full. Without `getDayContent`, days stay compact circles, and filled tiles are for days that have something to say.
  </Guideline.Dont>
</Guideline>

<Guideline title='Say what a modifier means'>
  <Guideline.Do>
    Explain a styled modifier in text near the calendar, such as "Bold nights have a show". Modifiers are styling only, and screen readers don't hear them.
  </Guideline.Do>
  <Guideline.Dont>
    Don't rely on colour alone to mark a modifier. Change the weight, add a mark or strike the day through.
  </Guideline.Dont>
</Guideline>

## Accessibility

- Each month is a `grid` named by its caption, such as "November 2026", and is `aria-multiselectable` in multiple and range modes. Each day is a button inside a `gridcell`, named by its full date with today and selection added, such as "Today, Friday, 27 November 2026, selected". Selected days also set `aria-selected` on the cell, and today has `aria-current='date'`.
- One day holds the tab stop: the focused day, then the selected day, then today. Focus moves separately from selection, so moving through the grid selects nothing.
- Arrow keys move by a day or a week. `Page Up` and `Page Down` move by a month, and with `Shift` by a year. `Home` and `End` move to the start and end of the week. Focus crosses into the next or previous month and the calendar follows, so no day is skipped.
- `Enter` and `Space` select the focused day. While a range is half chosen, `Escape` drops its start.
- Disabled days are focusable with `aria-disabled`, so they can be read and passed, but not selected.
- A polite live region announces the month when it changes and the selection when it changes, such as "Selected Wednesday, 3 to Sunday, 7 March 2027".
- The month arrows are labelled "Previous month" and "Next month", and in week view "Previous week" and "Next week". In the dropdown layout the selects are labelled "Month" and "Year". The view toggle is a button labelled "Month view", pressed in month view.
- Swiping turns the page on a touch screen, and the arrows do the same for everyone else. With reduced motion the days don't slide.
- In week view the grid is named by its dates, such as "Monday, 26 October to Sunday, 1 November 2026", and turning a week announces them.
- `getDayContent` describes its day: a day with a price is read as its date, then the price.
- With `layout='scroll'`, each month keeps its own column headers for screen readers, and the pinned weekday row is hidden from them.
