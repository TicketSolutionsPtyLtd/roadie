The `email` preset, for email designs, rendered to HTML with MJML, with merge
tags and conditions.

## Import

```tsx
import { Editor } from '@oztix/roadie-editor/editor'
import { renderEmail } from '@oztix/roadie-editor/email'
```

The [Editor](/components/editor) page covers the toolbar, emphasis, sizes,
states, and forms, which work the same in each preset.

## Examples

### Default

`preset='email'` is for composing an email. Its content sits in a canvas at
most 600 pixels wide, an email's width, spaced as the email will be: 16
pixels between blocks, and 16 above and below a section. A section or a
column shows a dashed outline under the pointer or the caret, drawn outside
it so it takes no room. Columns sit side by side from 480 pixels and stack below that, as
they do on a phone. It holds the text blocks of the rich preset, without
quotes, and an email's own blocks: sections, two to four columns, images,
buttons, spacers, and dividers.

This newsletter has a header image, a hero, two event cards, a lineup in
three columns, a section shown only when tickets are running low, and a
footer. Its greeting and button hold a merge tag, `first_name`, which shows
as a chip with the label from `variables`. Its footer links to two link
variables, the unsubscribe page and the email in a browser.

### Toolbar

An email opens with `toolbar='floating'`, as the blocks have their own
toolbars: select text to format it. It keeps its box, unlike a `blocks`
page, as an email isn't read on the page it's written on, and the box shows
where it ends. Pass `toolbar='docked'` for a bar across the top.

### The email's colours

The canvas stays light in a dark app, as the email it sends does. Pass the
same `theme` that `renderEmail` takes, and its background, text, links,
buttons, dividers, and font show in the canvas as they send, and a tinted
or accent section swaps its blocks' colours as the email does. Without one, the canvas takes `defaultEmailTheme`, as
`renderEmail` does, except that its links and strong buttons take the
accent of a `ThemeProvider` around the editor, which `renderEmail` doesn't
know, so pass `theme` for an exact match. Text outside columns sits 24
pixels in from each side of the canvas, so it wraps where it sends, and
columns reach 12 pixels further out, as they do in the email. The grip and
add button sit in the gutter beside the canvas, which the editor keeps
where the frame is too narrow for one. In a frame narrower than 544
pixels, as on a phone, the email sends at the screen's width, so the canvas
takes the frame's whole width with no gutter: the grip sits in the email's
own padding, and Blocks in the toolbar or `/` adds a block. A boxless
editor keeps its gutter for its handles. The outlines, the
caret's tint, selected text, and the placeholder mix from the theme's
colours, so they show on any background. A colour that isn't hex throws, as
it does in `renderEmail`.

### Adding blocks

There are two ways to add a block. Both list the blocks under the same
headings: Text, Media, Layout, Email, and Sections. Image shows only with
`onUploadImage`, and Merge tag is in the `/` menu only, with `variables`.

- **Blocks** in the toolbar opens a drawer of tiles, one per block, in its
  group. It starts the docked toolbar, so it shows on a phone, and ends the
  floating toolbar over a selection. The drawer opens from the right, or
  from the bottom on a phone. A tile adds its block after the block with the
  caret, and the drawer closes with the caret in the new block. On an empty
  line, the block takes the line's place, so no empty line is left behind,
  except one an empty button holds on its own. A section or columns picked in a column goes after the whole row,
  since columns can't hold one. Image and Button open the file picker and
  the link field on a new line there, or on the empty line. Find a block
  filters the tiles as `/` does, and from 1280 pixels wide the drawer
  leaves the email usable beside it, padding the editor's end so it covers
  none of the email.
- **Sections** lead the drawer and end the `/` menu. They're ready-made
  groups of blocks to edit: Header (also `/banner`), Event (`/tickets`,
  `/cta`), Two events, and Lineup. Each goes after the top-level block with
  the caret, or in place of an empty top-level line, never inside a section,
  and no empty line follows it, with its first line's text selected, so typing replaces it.
  Their buttons have no link until you set one, and send as text until then.
  Footer, also found as `/unsubscribe`, with a line on why the reader gets
  the email and an Unsubscribe link, shows when one of `variables` is a link
  variable whose key or label names the unsubscribe page.
- **`/`** opens the insert menu under the caret. Type to filter it. A
  heading with no matches hides, and the arrow keys step through the
  matches in the order shown, across the headings.

```tsx-live-prose
<Editor
  aria-label='Newsletter'
  preset='email'
  toolbar='docked'
  variables={[
    { key: 'unsubscribe_url', label: 'Unsubscribe page', kind: 'url', tokens: { ae: '#OptOut#', liquid: '{{ unsubscribe_url }}' } }
  ]}
  defaultValue={{
    version: 1,
    preset: 'email',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Ochre Kite Weekender' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Pick Blocks in the toolbar to add a block after this line.' }] }
      ]
    }
  }}
/>
```

### Moving and adding blocks

A grip and an add button show at the start of the block under the pointer,
or of the block with the caret while the editor has focus. Each block in a
section or column has its own, and so does a whole section or row of
columns: point at its edge to show it. A single column has none, as its
menu sets how many columns there are.

- **Drag the grip** to move the block. It lands in the section or column
  under the pointer, where a line shows, or at the top level outside them.
  A drop that place can't hold, such as a section in a column, shows no
  line and moves nothing. A section or column left with no blocks keeps an
  empty line.
- **Click or tap the grip**, or press `Mod+/` in the text, for the block's
  menu: Move up, Move down, Duplicate, and Delete. Move up and Move down go
  to the next place the block can go, into and out of sections and columns,
  so the keyboard reaches every place a drag does. For a block in a
  section or row of columns, Select section or Select columns turns the
  menu to the block holding it, to move a whole section by keyboard. In the
  text, `Mod+Shift+ArrowUp` and `Mod+Shift+ArrowDown` move the caret's block
  the same way, and `Mod+D` duplicates it.
- **The add button** opens the insert menu on a new line after the block,
  with the same items as `/`. On an empty line, such as in an empty section
  or column, it opens there.

Each move is one step to undo. On a touch screen the grip shows beside the
block you're typing in, and its menu moves the block.

### Composing a layout

Type `/` to insert a block at the caret, after a space or straight after a word, as in `7pm/section`; after a word it opens only once you type the start of a block's name, and not in a word with `.`, `:`, `/` or `@`, so dates such as `7/8` and links stay text. The list filters as you type, by the
start of each word in a block's name or its other names, such as `/h1`, `/img`,
`/hr`, `/btn`, or `/cta`, listing first a block whose name starts with what you typed, so `/2` offers 2 columns before Heading 2. The arrow keys move through it, Enter inserts, and
Escape closes it, keeping what you typed, as does moving focus away. When
nothing matches, a No blocks match row keeps it open, so Enter inserts nothing,
until you type a space. With a mouse or trackpad, each block made by markdown
shows its shortcut, such as `##` for Heading 2. One undo takes a block the menu inserts
back to what you typed; an image, embed, or button, which arrives after its
upload or link, takes a second. A paragraph, heading, or list turns the caret's line into
one. Any other block takes an empty line's place, goes before a line the `/` starts, or after a line with text, and a
section or columns puts the caret in its first line. Enter on the empty last
line of a section takes that line out after the section, as Enter on an empty
list item leaves the list, so what you type next isn't in the section. An
email can end with a section or columns, with no empty line after them. Only the blocks that fit
at the caret are offered, and only the other list type inside a list. Inside
a section, columns, or list, Section and columns that can't go there, and
the ready-made sections, go after that whole block instead, and the menu
says so beside them, such as "after this section". Enter at the end of a
button moves into an empty line already after it, so a second Enter leaves
a section. Image is offered with `onUploadImage`.

### Adding and editing merge tags

With `variables`, type `{{` anywhere, even straight after a word, to list
them under the caret. The list filters by label or key as you type, and Enter
inserts the active one as a chip. Merge tag in the `/` menu opens the same
list. A button's label takes merge tags too.

Click a chip to select it, and its toolbar shows below it: Edit merge tag and
Remove merge tag. Edit merge tag opens a form to change which variable the
tag shows and its fallback, the text anyone without a value sees. Each change
shows in the email as you make it. Enter in Fallback or a click away keeps
them, as one step to undo, and Escape puts the tag back as it was. An empty
fallback saves none. Without `variables`, `{{` is only text and `/` offers no Merge tag.

### Unsubscribe and view-in-browser links

Some links are made by the sending system for each customer, such as the
unsubscribe page or the email in a browser. List each as a variable with
`kind: 'url'`, and a link or a button can link to it in place of a web
address. A link variable is never a merge tag, so `{{` leaves it out.

- **A link:** select the text and press Link, or Mod+K. Under the address,
  Or link to lists each link variable. With nothing selected, it inserts the
  variable's label, linked.
- **A button:** Button settings has Links to, with A web address or each link
  variable.

The link saves the variable's key, `{ variable: 'unsubscribe_url' }`, with no
href.

### Buttons, columns, and spacers

Button asks for its link first, which must be a full web address, or a
`mailto:` or `tel:` link, as an email opens outside your site. A bare domain,
such as oztix.com.au, gets `https://`. The button's label is selected, so
typing replaces it, and Enter in a button starts a new paragraph after it.

Button settings, in the button's toolbar, edits its link and its look. Each
change shows on the button as it's made, so there's no Save. Enter in Link
or a click away keeps the changes, as one step to undo, and Escape puts the
button back as it was. A link applies once it's a full address, and the button keeps
its last one until then.

- **Emphasis:** Strong, a fill in the theme's accent, for the action that
  matters. Normal, a neutral border, or Subtle, a neutral tint, for one beside
  it.
- **Width:** Fit label, or Full width across its column.
- **Align:** Left, Centre, or Right in its column. A full-width button has
  none.

A button saves only what differs from a strong, left-aligned button at its
label's width: `align`, `emphasis: 'normal' | 'subtle'`, and
`fullWidth: true`. On the page, a button takes the colours of
[`theme`](#the-emails-colours), as the email does.

Each of these blocks has its own toolbar:

- **A button**, with the caret in it: Button settings and Remove button, below
  it.
- **Columns**, with the caret in them: a menu of 2, 3, or 4 columns, above
  them, or below when they start the content. Removing columns moves their
  blocks into the last column left, and undo puts them back.
- **A selected merge tag**: Edit merge tag and Remove merge tag, below it.
- **A selected spacer**: a Height menu of Small (16px), Medium (32px), Large
  (64px), and Extra large (96px), and Remove spacer.

An image the email shows must be served over https, as a mail client loads it
from outside your site. An `onUploadImage` that resolves to a path on the site
shows an error and adds nothing.

### Importing HTML or MJML

Import HTML or MJML, in the toolbar, or in the floating toolbar's … menu,
brings an existing email across. Paste its source, whole or in part, and the
dialog says whether it's reading MJML, which starts with `<mjml>`, or HTML.
Before anything changes, it lists what won't come across: styles, a table's
layout, images not on https, links an email can't open, hidden text such as a
preheader, and merge tags the editor doesn't know. Text is always kept. To send an email as written,
with its own look, save it as an [HTML email](#html-emails) instead.

Into an empty email, Import fills it. With content, Put it chooses Below the
cursor, the default, or In place of the whole email, which undo reverses.
Pasting markup as text, such as source copied from a code editor, opens the
same dialog with it filled in, in place of pasting the tags.

- **MJML:** each `mj-section` with one column becomes its blocks, two to four
  columns become columns, and an `mj-wrapper` or `mj-hero` becomes a section.
  `mj-text` is read as HTML, and `mj-button`, `mj-image`, `mj-spacer`, and
  `mj-divider` become a button, image, spacer, and divider. A button keeps
  its centre or right alignment and a 100% width. A navbar or social row
  becomes a line of links. Any other element keeps its text.
- **HTML:** a table layout gives way to its text and images, in order.
- **Merge tags:** a token from `variables`, such as `#FirstName#` or
  `{{ customer.first_name }}`, becomes its merge tag, and a Liquid
  `default` becomes its fallback. A link or button whose whole href is a link
  variable's token, such as `#OptOut#`, links to that variable.

Try it with this source:

```html
<mjml><mj-body><mj-section><mj-column>
  <mj-text><h2>Doors 7pm</h2><p>Hi #FirstName#, the gates open at Jumbuck Orchard Park on Saturday.</p></mj-text>
  <mj-button href="https://www.oztix.com.au/ochre-kite-weekender" align="center">Get tickets</mj-button>
  <mj-text><a href="#OptOut#">Unsubscribe</a></mj-text>
</mj-column></mj-section></mj-body></mjml>
```

```tsx-live-prose
<Editor
  aria-label='Imported email'
  preset='email'
  variables={[
    { key: 'first_name', label: 'First name', tokens: { ae: '#FirstName#', liquid: '{{ customer.first_name }}' } },
    { key: 'unsubscribe_url', label: 'Unsubscribe page', kind: 'url', tokens: { ae: '#OptOut#', liquid: '{{ unsubscribe_url }}' } }
  ]}
/>
```

`importEmail(source, { variables })` from `@oztix/roadie-editor/schema` is
the same import, for a migration script or your own UI. It runs in a browser,
with no MJML package, and returns the value with what it couldn't keep.

```ts
import { importEmail } from '@oztix/roadie-editor/schema'

const { value, format, dropped, restyled, unknownMergeTags } = importEmail(
  source,
  { variables }
)
```

`dropped` lists images, embeds, hidden text, links on images, links an
email can't open, such as `javascript:`, and MJML elements with no block of their own, in order. `restyled` counts style sheets
and styled elements, and tables, outermost only. `unknownMergeTags` lists
each token no variable matches, kept as text.

## Sending email

`@oztix/roadie-editor/email` renders a design, an `EditorValue` in the email
preset, as an email: a whole HTML page, built from tables with inline styles
so mail clients show it as designed, and its plain-text part.

```tsx
import { renderEmail } from '@oztix/roadie-editor/email'

const { html, text } = await renderEmail({ kind: 'design', value: template }, {
  theme: { accent: '#5f270f' }
})
```

It runs on the server only, since MJML, the renderer behind it, needs Node.
A Next.js app keeps MJML out of its server bundle, and adds `mjml` to its own
dependencies too, so Next can resolve it from the app:

```ts
// next.config.ts
const nextConfig = { serverExternalPackages: ['mjml'] }
```

- `theme` is the app's brand kit, over `defaultEmailTheme`: `background`,
  `text`, `accent`, `link`, `button`, `buttonText`, `border`, `tint`, and
  `divider` as hex colours, and
  `fontFamily` as a stack of web-safe fonts. Mail clients don't read CSS
  variables, so the default is Roadie's light scales as hex. Keep the kit in
  the app, never in the saved value. A colour that isn't hex, or a font
  stack with more than names, quotes, and commas, throws. Links and strong
  buttons take `accent`, Oztix blue by default, unless `link` or `button` is
  set. A normal button draws its border in `border` and a subtle one fills
  with `tint`.
- A section, and a run of blocks outside columns, fill the email's 600 pixel
  width. Columns sit side by side from 480 pixels and stack on a phone, and
  stay side by side in Outlook on Windows.
- `text` writes each link as its text then its href in brackets, unless the
  two match, and leaves out images, spacers, and dividers.

It reads the value into the email preset first, as `migrate` does, so a value
from another preset renders too, keeping its text. A link or button needs an
https, http, mailto, or tel href, since a mail client can't open a path on the
site, so any other keeps its text and loses its link.

### HTML emails

An email pasted in from another tool, or made outside the editor, is kept as
written, since reading it into a design would lose its layout.
`EmailHtmlField` edits its source, with a preview at 600 pixels and on a
phone. Pasting keeps the clipboard's HTML rather than its text, unless the
text is itself markup, as source copied from a code editor is.

```tsx
import { EmailHtmlField } from '@oztix/roadie-editor/email-html-field'
```

```tsx-live-noinline
const template = `<table role="presentation" width="100%" bgcolor="#f4f4f4">
  <tr><td align="center" style="padding:24px">
    <table role="presentation" width="100%" style="max-width:560px" bgcolor="#ffffff">
      <tr><td style="padding:24px;font-family:Arial,sans-serif;color:#333333">
        <h1 style="margin:0 0 12px;font-size:24px">Ochre Kite Weekender</h1>
        <p style="margin:0 0 16px">Hi #FirstName#, doors open 7pm at Jumbuck Orchard Park.</p>
        <a href="https://www.oztix.com.au/ochre-kite-weekender"
          style="display:inline-block;padding:12px 20px;background:#5f270f;color:#ffffff;text-decoration:none">
          Get tickets
        </a>
      </td></tr>
    </table>
  </td></tr>
</table>`

function HtmlEmail() {
  const [html, setHtml] = useState(template)
  return (
    <Field>
      <Field.Label>Email HTML</Field.Label>
      <EmailHtmlField value={html} onValueChange={setHtml} />
      <Field.ErrorText />
    </Field>
  )
}

render(<HtmlEmail />)
```

The preview is a sandboxed frame, so it runs none of the email's scripts and
submits none of its forms. A script, an event handler such as `onclick`, or a
`javascript:` link shows a warning in `Field.ErrorText`, since mail clients
won't run them either. The field never rewrites the HTML: the sending app's
sanitiser stays the gate.

```tsx-live
<Field>
  <Field.Label>Email HTML</Field.Label>
  <EmailHtmlField defaultValue={'<a href="https://www.oztix.com.au/ochre-kite-weekender" onclick="track()">Get tickets</a>'} />
  <Field.ErrorText />
</Field>
```

Save it as `{ kind: 'html', html }`, an `EmailContent`, never in an
`EditorValue`. `renderEmail` sends it unchanged, merge tags and Outlook's
`[if mso]` blocks included, with a plain-text part written from it:

```tsx
import { renderEmail } from '@oztix/roadie-editor/email'

const { html, text } = await renderEmail({ kind: 'html', html: pasted })
```

### Merge tags

A merge tag, such as the customer's first name, is a `variable` node in the
email preset. It saves only its key and an optional fallback, never the token
a sending system reads, so one template sends from either system.

```ts
const welcome = {
  version: 1,
  preset: 'email',
  doc: {
    type: 'doc',
    content: [
      {
        type: 'paragraph',
        content: [
          { type: 'text', text: 'Hi ' },
          { type: 'variable', attrs: { key: 'first_name', fallback: 'there' } },
          { type: 'text', text: ', your tickets are ready.' }
        ]
      }
    ]
  }
}
```

The app lists the variables its sending system fills, each with a label and
its token in each syntax. A filter, such as a date format, belongs in the
token, never in the template. Pass the same list to `Editor` as `variables`:
each merge tag shows as a chip with its label, and one whose key isn't listed
shows as invalid.

```tsx
import { type EditorVariable, renderEmail } from '@oztix/roadie-editor/email'

const variables: EditorVariable[] = [
  {
    key: 'first_name',
    label: 'First name',
    tokens: { ae: '#FirstName#', liquid: '{{ customer.first_name }}' }
  },
  {
    key: 'event_date',
    label: 'Event date',
    tokens: { liquid: '{{ event.date | date: "%-d %B" }}' }
  },
  {
    key: 'unsubscribe_url',
    label: 'Unsubscribe page',
    kind: 'url',
    tokens: { ae: '#OptOut#', liquid: '{{ unsubscribe_url }}' }
  }
]

// Hi {{ customer.first_name | default: "there" }}, your tickets are ready.
const { html, text } = await renderEmail({ kind: 'design', value: welcome }, {
  syntax: 'liquid',
  variables
})

// Hi Ashley, your tickets are ready.
const preview = await renderEmail({ kind: 'design', value: welcome }, {
  variables,
  values: { first_name: 'Ashley' }
})
```

- `syntax` is `ae` for `#Token#` or `liquid` for `{{ }}`. Each variable is
  written as its token, unescaped, in the HTML and the plain text alike.
- A Liquid token of one `{{ }}` output gets the fallback as its `default`.
  An AE token has no default, so its fallback isn't written.
- With `values`, each variable is filled with its value, escaped, or its
  fallback when the value is missing or empty. A preview needs no `syntax`.
- A variable `variables` doesn't list, or one with no token in `syntax`,
  throws, so a template never asks for a value the sender can't fill.
- Text an author typed that reads as a token, such as `{{ code }}` or
  `#FirstName#`, is written so no sending system fills it.
- A merge tag never goes in a link's or a button's href. A link variable
  does: its token is written as the href, so it must write a whole URL. With
  `values`, the href is its value, and with no value a mail client can open,
  the text stays unlinked.
- An HTML email's merge tags are already tokens, so it's sent unchanged,
  whatever the options.

### Conditions

A section, button, image, spacer, or divider in the email preset can show
only to some recipients, such as a "last few tickets" section when an event
is nearly sold out. Its `showWhen` rule names a variable by key, never as
Liquid, so the rule can be checked against the variables the sender fills.

```ts
const nearlySoldOut = {
  version: 1,
  preset: 'email',
  doc: {
    type: 'doc',
    content: [
      {
        type: 'section',
        attrs: {
          showWhen: { key: 'tickets_left', op: 'lessThan', value: 20 }
        },
        content: [
          {
            type: 'paragraph',
            content: [{ type: 'text', text: 'Only a few tickets left.' }]
          }
        ]
      },
      {
        type: 'paragraph',
        content: [{ type: 'text', text: 'See you at the Ochre Kite Weekender.' }]
      }
    ]
  }
}
```

```tsx
import { type EditorVariable, renderEmail } from '@oztix/roadie-editor/email'

const variables: EditorVariable[] = [
  {
    key: 'tickets_left',
    label: 'Tickets left',
    tokens: { liquid: '{{ event.tickets_left }}' }
  }
]

// {% if event.tickets_left < 20 %} … {% endif %}
const { html, text } = await renderEmail({ kind: 'design', value: nearlySoldOut }, {
  syntax: 'liquid',
  variables
})

// Leaves the section out.
const preview = await renderEmail({ kind: 'design', value: nearlySoldOut }, {
  variables,
  values: { tickets_left: '200' }
})
```

- `op` is `exists`, `equals`, `notEquals`, `lessThan`, or `greaterThan`.
  `exists` takes no `value`. `equals` and `notEquals` take text or a number,
  and `lessThan` and `greaterThan` a number.
- A number is compared as a number and text as text, as Liquid compares
  them, so `20` and `'20'` are different rules. The sender's value must be
  the same type as the rule's.
- Columns and text blocks take no rule. To show a paragraph only to some
  recipients, put it in a section with the rule.
- With `syntax: 'liquid'`, the block is wrapped in `{% if %}` and
  `{% endif %}` in the HTML and the plain text. The variable's Liquid token
  must be a plain variable, such as `{{ event.tickets_left }}`, since Liquid
  takes no filters in a condition.
- With `values`, the block shows only when its rule holds. A missing or
  empty value, or `'false'`, doesn't exist, as Liquid's `false` doesn't,
  and `'false'` equals no text. A value that isn't a number is never less
  or greater than one. A preview value is a number when it's written in
  decimal digits.
- The `ae` syntax has no conditions, so a rule throws there. So does a rule
  with neither `syntax` nor `values`, one naming a variable `variables`
  doesn't list or whose Liquid token isn't a plain variable, a number Liquid
  can't write, such as `1e21`, and text holding both quote marks or `%}`,
  which a Liquid string can't hold.
- `migrate` trims a rule's key, drops a rule that isn't whole, and keeps its
  block.

## Accessibility

- In the email preset, `/` opens a `listbox` named Insert under the caret.
  Focus stays in the text, which points `aria-activedescendant` at the active
  option and `aria-controls` at the list. Each heading's options sit in a
  `group` named for it. With `variables`, `{{` opens a `listbox` named Merge
  tags the same way.
- Blocks in the toolbar opens a `dialog` named Blocks, with focus on its
  first tile. A search field named Find a block comes first. Each heading's
  tiles sit in a `group` named for it, and the tiles take one Tab stop: the
  arrow keys move between them, across the headings, Home and End go to the
  first and last, ArrowUp from the top row goes to the search field, and
  typing a letter types it there. Enter or Space adds a block, and Escape closes the
  drawer. Either way, focus goes back to the text, or to the link field
  after Button.
- In the email preset, a button's, a spacer's, columns', or a merge tag's own
  toolbar is named for it, such as "Button actions" or "Merge tag actions", and
  Alt+F10 moves focus into it.
  The Columns and Height menus' triggers are named for their current choice,
  such as "Columns: 2 columns".

- The grip is a button named Block actions, and the add button is named Add
  block. Neither takes a Tab stop, since they show only beside the caret's
  block; `Mod+/` opens the block's menu, and `/` the insert menu.

| Keys | Action |
| --- | --- |
| `/` | Open the insert menu, in the email preset |
| `Alt+F10`, then `Enter` | Open the Blocks drawer from the docked toolbar |
| `{{` | Open the merge tag list, with `variables` |
| `Mod+/` | Open the menu for the block with the caret |
| `Enter` | In a button, start a new paragraph after it |

Every preset's other keys are on the [Editor](/components/editor#accessibility)
page.
