The `blocks` preset, for CMS pages built from blocks, with the insert menu,
drag and the block menu, and custom blocks.

## Import

```tsx
import { Editor } from '@oztix/roadie-editor/editor'
```

The [Editor](/components/editor) page covers the toolbar, emphasis, sizes,
states, and forms, and [Basic and rich](/components/editor/basic-and-rich)
the images, embeds, and tables this preset holds too.

## Examples

### Default

`preset='blocks'` holds everything the rich preset does, for a page built
from blocks, and every block keeps an id as it moves. Type `/` to add a
block. An empty page, and the empty line with the caret while the editor has
focus, say so: "Type / to add a block". A `placeholder` replaces it, and shows
only while the page is empty.

A page is edited in place, so a `blocks` editor opens with
`emphasis='subtler'`, with no box, and `toolbar='floating'`: select text to
format it. Pass `emphasis` or `toolbar` to change either. An
[email](/components/editor/email) floats its toolbar too, but keeps its box.

```tsx-live-prose
<Editor
  aria-label='Page'
  preset='blocks'
  defaultValue={{
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Ochre Kite Weekender' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Two days in the sun at Jumbuck Orchard Park, Brisbane.' }] },
        { type: 'paragraph' }
      ]
    }
  }}
/>
```

Every block but a table's rows and cells saves a `blockId`, so it keeps its
identity as it moves. The editor gives a block without one an id when it
loads, splits, or is pasted, and `onValueChange` reports it. Copying a block
gives the copy an id of its own. `/render` never writes ids into the page.

Give each record's editor its own `key`, such as the record's id. An editor
reused for another record reads that record's id-less blocks as the ones it
already holds when their content matches, so it keeps the first record's ids.

### Inserting blocks

Type `/` to open the same insert menu as the
[email preset](/components/editor/email#composing-a-layout), with the same keys. It offers
Paragraph, Heading 2 to 4, Bulleted list, Numbered list, and Quote under
Text, Image and Embed under Media, and Divider and Table under Layout, then
More for an app's own blocks. It offers only those that fit at the caret, so
a table cell offers Paragraph alone. Image shows with `onUploadImage` and
opens the file picker, and Embed opens the Embed popover. Other names find
blocks too: `/youtube` or `/link` for Embed, `/h1` or `/title` for a heading,
`/ul`, `/ol`, `/hr`, `/---`, and `/>`. Each block that markdown makes shows
its shortcut, such as `##` or `---`, with a mouse or trackpad.

**Blocks** in the toolbar, docked or floating, opens a drawer of the same
blocks as tiles under their headings, from the right on a desktop or the
bottom on a phone. A tile adds its block after the caret's, and the drawer
closes with the caret in it. Find a block, at its top, filters the tiles as
`/` does; typing on a tile types there, and Enter adds the first match. The
arrow keys move between tiles. From 1280 pixels wide the drawer leaves the
page usable beside it, with no backdrop, so you can move the caret without
closing it. The [email preset](/components/editor/email#composing-a-layout)
has the same drawer.

### Block handle

A grip shows at the start of the block under the pointer, or of the block
with the caret while the editor has focus. Drag it to move the block; a line
shows where it will land. Click or tap it, or press `Mod+/` in the text, for
the block's menu: Move up, Move down, Duplicate, and Delete. The menu opens
beside the grip, headed by the block's type, with each action's keys, and
the block takes the chosen tint while it's open, so it's clear which block
it acts on. Each is one step to undo, a moved block keeps its `blockId`,
and a copy gets one of its own. On a touch screen the grip shows beside the
block you're typing in, and its menu moves the block. The add button
before the grip opens the insert menu on a new line after the block, or in
the block itself when it's an empty line.

```tsx-live-prose
<Editor
  aria-label='Set times'
  preset='blocks'
  defaultValue={{
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Set times' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Doors, 7pm' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'The Saltbush Echoes, 8pm' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Velvet Kookaburra, 9:30pm' }] }
      ]
    }
  }}
/>
```

A framed editor makes room for the add button and grip at the start of its
text. A `subtler` editor keeps its text in line with the page, so they hang
outside it: give it room at the start.

The grip is a button named Block actions. It takes no Tab stop, since it
shows only beside the caret's block; `Mod+/` opens its menu instead. The
menu's items are `menuitem`s. Move up and Move down are disabled at
the first and last blocks. Closing the menu puts focus back in the text.

| Keys | Action |
| --- | --- |
| `Mod+/` | Open the menu for the block with the caret |
| `Mod+Shift+ArrowUp`, `Mod+Shift+ArrowDown` | In the text, move the caret's block up or down |
| `Mod+D` | In the text, duplicate the caret's block |
| `ArrowDown`, `ArrowUp` | In the menu, move between actions |
| `Enter` | Run the action |
| `Delete`, `Backspace` | In the menu, delete its block |
| `Escape` | Close the menu, back to the text |

### Custom blocks

An app adds its own blocks, such as a call to action or an event feed, with
`extensions`. Build each from `@oztix/roadie-editor/extensions`, which
re-exports Tiptap's `Node` and `mergeAttributes`, so the app never installs
Tiptap or drifts from Roadie's version:

```tsx
import {
  Node,
  NodeViewWrapper,
  reactNodeView
} from '@oztix/roadie-editor/extensions'
```

- A block is an atom (`group: 'block'`, `atom: true`). Its attrs are all it
  saves, so keep them to its inputs, such as `{ label, href }`, never
  rendered content.
- `reactNodeView(Component)`, returned from the node's `addNodeView`, edits
  it in place. The component gets `node.attrs` and `updateAttributes`, and
  wraps what it renders in `NodeViewWrapper`. Typing in its inputs edits
  them, not the text around the block. A read-only or disabled editor
  ignores its `updateAttributes` and `deleteNode`.
- Pass `{ node, label, icon, keywords }` in `extensions` to show it in the
  insert menu, under More and only where it fits. Add `group` to list it
  under one of the preset's headings, such as Media, or a heading of its
  own. The editor reads `extensions` once, when it's created, so give it a
  new `key` to change them.
- Render it with `renderEditorValue(value, { nodeMapping })`, an entry per
  block that gets its `attrs`. Read each as untrusted input. A block with no
  entry is dropped, never shown raw, and so is every custom block in
  `renderEditorHtml`.
- `migrate(value, 'blocks', { customBlocks: ['callToAction'] })` keeps them
  in a stored value. The editor and `renderEditorValue` pass these for you.
- A block can't take the name of one of the preset's own nodes or marks;
  the editor leaves it out.
- `/extensions` brings Tiptap with it, so import your blocks where the
  editor loads, not on every page. Keep `nodeMapping` in a file of its own,
  so a server page that renders saved content doesn't import Tiptap.

```tsx-live-prose-noinline
function CallToActionView({ node, updateAttributes }) {
  return (
    <NodeViewWrapper className='grid gap-2 rounded-xl emphasis-subtle p-3'>
      <Field>
        <Field.Label>Button</Field.Label>
        <Field.Input
          value={node.attrs.label}
          onChange={(event) => updateAttributes({ label: event.target.value })}
        />
      </Field>
      <Field>
        <Field.Label>Link</Field.Label>
        <Field.Input
          value={node.attrs.href}
          onChange={(event) => updateAttributes({ href: event.target.value })}
        />
      </Field>
    </NodeViewWrapper>
  )
}

const callToAction = {
  label: 'Call to action',
  icon: TicketIcon,
  keywords: ['button'],
  node: Node.create({
    name: 'callToAction',
    group: 'block',
    atom: true,
    addAttributes: () => ({
      label: { default: 'Get tickets' },
      href: { default: '/events/ochre-kite-weekender' }
    }),
    renderHTML: ({ HTMLAttributes }) => ['div', mergeAttributes(HTMLAttributes)],
    addNodeView: () => reactNodeView(CallToActionView)
  })
}

// Stored attrs are untrusted, so the link is kept only when it's a site path.
const sitePath = (href) =>
  typeof href === 'string' && /^\/(?!\/)/.test(href) ? href : undefined

const nodeMapping = {
  callToAction: ({ attrs }) => (
    <Button href={sitePath(attrs.href)} intent='brand' emphasis='strong'>
      {String(attrs.label)}
    </Button>
  )
}

function Page() {
  const [value, setValue] = useState({
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Ochre Kite Weekender' }] },
        { type: 'callToAction', attrs: { label: 'Get tickets', href: '/events/ochre-kite-weekender' } },
        { type: 'paragraph' }
      ]
    }
  })
  return (
    <>
      <Editor
        aria-label='Page'
              extensions={[callToAction]}
        value={value}
        onValueChange={setValue}
      />
      {renderEditorValue(value, { nodeMapping })}
    </>
  )
}

render(<Page />)
```

## Accessibility

- In the blocks preset, `/` opens a `listbox` named Insert under the caret.
  Focus stays in the text, which points `aria-activedescendant` at the active
  option and `aria-controls` at the list.
- The grip and its menu, with their keys, are under
  [Block handle](#block-handle).

| Keys | Action |
| --- | --- |
| `/` | Open the insert menu, in the blocks preset |

Every preset's other keys are on the [Editor](/components/editor#accessibility)
page.
