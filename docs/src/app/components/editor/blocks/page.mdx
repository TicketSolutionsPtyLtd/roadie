The `blocks` preset, for CMS pages built from blocks, with the insert menu,
drag and the block menu, and custom blocks.

## Import

```tsx
import { Editor } from '@oztix/roadie-editor/editor'
```

The [Editor](/components/editor) page covers the toolbar, emphasis, sizes,
states, and forms, and [Basic and rich](/components/editor/basic-and-rich)
the images, embeds, and tables this preset holds too.

## Examples

### Default

`preset='blocks'` holds everything the rich preset does, for a page built
from blocks, and every block keeps an id as it moves. Type `/` to add a
block. An empty page, and the empty line with the caret while the editor has
focus, say so: "Type / to add a block", or on a touch screen, where `/` is a keyboard layer away, "Tap Blocks to add a block". A `placeholder` replaces it, and shows
only while the page is empty.

A page is edited in place, so a `blocks` editor opens with
`emphasis='subtler'`, with no box, and `toolbar='floating'`: select text to
format it. Pass `emphasis` or `toolbar` to change either. An
[email](/components/editor/email) floats its toolbar too, but keeps its box.

```tsx-live-prose
<Editor
  aria-label='Page'
  preset='blocks'
  defaultValue={{
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Ochre Kite Weekender' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Two days in the sun at Jumbuck Orchard Park, Brisbane.' }] },
        { type: 'paragraph' }
      ]
    }
  }}
/>
```

Every block but a table's rows and cells saves a `blockId`, so it keeps its
identity as it moves. The editor gives a block without one an id when it
loads, splits, or is pasted, and `onValueChange` reports it. Copying a block
gives the copy an id of its own. `/render` never writes ids into the page.

Give each record's editor its own `key`, such as the record's id. An editor
reused for another record reads that record's id-less blocks as the ones it
already holds when their content matches, so it keeps the first record's ids.

### Inserting blocks

Type `/` to open the same insert menu as the
[email preset](/components/editor/email#composing-a-layout), with the same keys. It offers
Paragraph, Heading 2 to 4, Bulleted list, Numbered list, and Quote under
Text, Image and Embed under Media, and Divider and Table under Layout, then
More for an app's own blocks. It offers only those that fit at the caret, so
a table cell offers Paragraph alone. Image shows with `onUploadImage` and
opens the file picker, and Embed opens the Embed popover. Other names find
blocks too: `/youtube` or `/link` for Embed, `/h1` or `/title` for a heading,
`/ul`, `/ol`, `/hr`, `/---`, and `/>`. Each block that markdown makes shows
its shortcut, such as `##` or `---`, with a mouse or trackpad.

**Blocks** in the toolbar, docked or floating, opens a drawer of the same
blocks as tiles under their headings, from the right on a desktop or the
bottom on a phone. A tile adds its block after the caret's, and the drawer
closes with the caret in it. Find a block, at its top, filters the tiles as
`/` does; typing on a tile types there, and Enter adds the first match. The
arrow keys move between tiles. From 1280 pixels wide the drawer leaves the
page usable beside it, with no backdrop, so you can move the caret without
closing it. The [email preset](/components/editor/email#composing-a-layout)
has the same drawer.

### Block handle

A grip shows at the start of the block under the pointer, or of the block
with the caret while the editor has focus. Drag it to move the block; a line
shows where it will land. Click or tap it, or press `Mod+/` in the text, for
the block's menu: Move up, Move down, Duplicate, Turn into, Insert below,
Copy link to block, and Delete, led by Settings on a block that has them.
The menu opens beside the grip, clear of the text, or below it where the
page has no room beside it. `Mod+/` opens it with its first action ready for
`Enter`. It's headed by the block's type, with each action's keys, and the
block takes the chosen tint while it's open, so it's clear which block it
acts on. Each is one step to undo, a moved block keeps its `blockId`, and a
copy gets one of its own. The add button before the grip opens the insert
menu on a new line after the block, or in the block itself when it's an
empty line.

- **Move up** and **Move down** leave the menu open on the block, so it can
  move again.
- **Turn into** makes a text block a paragraph, a heading, a list, or a
  quote, keeping its text and its `blockId`.
- **Insert below** opens a line under the block with the insert menu.
- **Copy link to block** copies the page's address with the block's
  `blockId` as its hash, and says Link copied by the grip. Opening the
  address scrolls the editor to the block.

On a phone or a touch screen the grip shows beside the block you're typing
in, following the caret onto a new line, with a 44px target, and the text
is inset at its start by the grip's room, in a `subtler` editor too, so the
page can't clip it. Its menu opens as a sheet over the lower half of the
screen, with the block scrolled into the half above, which stays undimmed.
The sheet leads with Move up and Move down buttons and Done, then Turn into
and Move to, each a step of its own, the other actions, and Delete last.
Move to lists the page's headings and sections, and puts the block under
the one tapped, as one step to undo.

```tsx-live-prose
<Editor
  aria-label='Set times'
  preset='blocks'
  defaultValue={{
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Set times' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Doors, 7pm' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'The Saltbush Echoes, 8pm' }] },
        { type: 'paragraph', content: [{ type: 'text', text: 'Velvet Kookaburra, 9:30pm' }] }
      ]
    }
  }}
/>
```

The editor makes room for the add button and grip at the start of its text, in a
`subtler` editor too, so neither its host nor a frame clips it. The grip
sits on a block's first line of text, below a section's padding, and keeps
its place as the editor resizes.

The grip is a button named Block actions. It takes no Tab stop, since it
shows only beside the caret's block; `Mod+/` opens its menu instead. The
menu's items are `menuitem`s. Move up and Move down are disabled at
the first and last blocks. Closing the menu puts focus back in the text.

| Keys | Action |
| --- | --- |
| `Mod+/` | Open the menu for the block with the caret |
| `Mod+Shift+ArrowUp`, `Mod+Shift+ArrowDown` | In the text, move the caret's block up or down |
| `Mod+D` | In the text, duplicate the caret's block |
| `ArrowDown`, `ArrowUp` | In the menu, move between actions |
| `Enter` | Run the action |
| `Delete`, `Backspace` | In the menu, delete its block |
| `Escape` | Close the menu, back to the text |

### Sections

`sections` adds designed sections, such as a hero or a row of cards, drawn
in the editor as the page draws them. `catalogueSections()` from
`@oztix/roadie-blocks/catalogue/sections` makes them from the blocks you
pass, so a page loads only those:

```tsx
import { catalogueSections } from '@oztix/roadie-blocks/catalogue/sections'
```

- Each block is a section, and each of its presets a template, listed under
  Sections in `/` and as a tile with the preset's thumbnail in the Blocks
  drawer. Serve the package's `thumbnails` folder and pass `thumbnailUrl`;
  without it, tiles show an icon.
- A section is one block, drawn across the page rather than in the text's
  measure. With a mouse, a click opens its Settings at the text you
  clicked, such as its title, and the page stays usable beside them. On a
  touch screen a tap selects it, and Settings is in its menu. Settings edit
  every part of it: its layout, text, alignment, size, surface, and colour,
  its images and buttons, and its items, such as cards or questions, which
  you add, remove, and drag to reorder. A click on a card or question opens
  its fold. Only the settings its layout reads show. Its links and buttons
  can't be followed or focused while you edit.
- Each block has keywords too, so `/cta` finds Call to action and
  `/questions` finds FAQ.
- `content` gives each template its starting attrs, such as an app's
  images, cards, or questions, over the placeholder copy.
- Render it with `renderEditorValue(value, { nodeMapping })`, an entry per
  section from its `render`:
  `Object.fromEntries(sections.map(({ name, render }) => [name, render]))`.
- Each saves its fields as attrs, under its node name, such as
  `heroSection`, so that name stays put once pages hold it. A section reads
  its saved lists as lists, and in the editor one that still can't be drawn
  shows a message in its place.

```tsx-live-prose-noinline
const photo = { src: '/brand/photography/08.webp', alt: '', width: 1280, height: 850 }

const sections = catalogueSections({
  components: { hero: Hero, cards: Cards, faq: FAQ, 'call-to-action': CallToAction },
  thumbnailUrl: blockThumbnailUrl,
  content: (block, preset) => ({
    title: 'Ochre Kite Weekender',
    description: 'Two days in the sun at Jumbuck Orchard Park, Brisbane.',
    ...(preset.fields.includes('image') && { image: photo }),
    ...(block.name === 'cards' && {
      cards: [
        { title: 'Camping', description: 'Pitch a tent by the main stage.' },
        { title: 'Food', description: 'Twenty stalls, open till late.' },
        { title: 'Getting there', description: 'Shuttles run from the city.' }
      ]
    }),
    ...(block.name === 'faq' && {
      questions: [
        { question: 'Is it all ages?', answer: 'Yes, under 16s come with an adult.' }
      ]
    })
  })
})

render(
  <Editor
    aria-label='Page'
    sections={sections}
    defaultValue={{
      version: 1,
      preset: 'blocks',
      doc: {
        type: 'doc',
        content: [
          { type: 'heroSection', attrs: { preset: 'title', eyebrow: 'Brisbane', title: 'Ochre Kite Weekender', description: 'Two days in the sun at Jumbuck Orchard Park.' } },
          { type: 'paragraph', content: [{ type: 'text', text: 'Type / and search for cards, or pick Blocks.' }] }
        ]
      }
    }}
  />
)
```

### Custom blocks

An app adds its own blocks, such as a call to action or an event feed, with
`extensions`. Build each from `@oztix/roadie-editor/extensions`, which
re-exports Tiptap's `Node` and `mergeAttributes`, so the app never installs
Tiptap or drifts from Roadie's version:

```tsx
import {
  Node,
  NodeViewWrapper,
  reactNodeView
} from '@oztix/roadie-editor/extensions'
```

- A block is an atom (`group: 'block'`, `atom: true`). Its attrs are all it
  saves, so keep them to its inputs, such as `{ label, href }`, never
  rendered content.
- Give it `settings`, and its view can show it as the page will, not as a
  form. With a mouse, a click on the block opens them at the text clicked,
  such as a card's title; on a touch screen a tap selects it. Settings also
  leads its block menu, and Enter on the selected block opens them. They
  open in a drawer from the side that leaves the page usable, and makes room
  for the block beside it on a wide page, or a sheet under half the screen
  on a phone, with a field for each:
  - `text`: a line, or a few with `multiline`.
  - `choice`: its `options` as buttons, or a select past three, with
    `defaultValue` chosen while its attr is unset.
  - `image`: `{ src, alt }`, from a link or, with `onUploadImage`, an upload.
  - `action`: `{ label, href }`, such as a button.
  - `list`: items to add, remove, and drag or move to reorder, each in its
    own fold, of `fields`, or of an `item` that's an `image` or an `action`.

  Each change shows as it's made. Done, Escape, Enter in a text setting, or
  a click or tap away keeps the changes, and Undo takes the whole visit back
  in one step. The caret goes back where it was before the block was
  selected, or after the block, so the next key types rather than replacing
  it. Opened from the keyboard with Enter, the block stays selected.
- `reactNodeView(Component)`, returned from the node's `addNodeView`, edits
  it in place. The component gets `node.attrs` and `updateAttributes`, and
  wraps what it renders in `NodeViewWrapper`. Typing in its inputs edits
  them, not the text around the block, and `Mod+Z` and `Mod+Shift+Z` there
  step the editor's history, so each edit undoes as text does. A read-only
  or disabled editor ignores its `updateAttributes` and `deleteNode`.
- Pass `{ node, label, icon, keywords }` in `extensions` to show it in the
  insert menu, under More and only where it fits. Add `group` to list it
  under one of the preset's headings, such as Media, or a heading of its
  own. The editor reads `extensions` once, when it's created, so give it a
  new `key` to change them.
- Render it with `renderEditorValue(value, { nodeMapping })`, an entry per
  block that gets its `attrs`. Read each as untrusted input. A block with no
  entry is dropped, never shown raw, and so is every custom block in
  `renderEditorHtml`.
- `migrate(value, 'blocks', { customBlocks: ['callToAction'] })` keeps them
  in a stored value. The editor and `renderEditorValue` pass these for you.
- A block can't take the name of one of the preset's own nodes or marks;
  the editor leaves it out.
- `/extensions` brings Tiptap with it, so import your blocks where the
  editor loads, not on every page. Keep `nodeMapping` in a file of its own,
  so a server page that renders saved content doesn't import Tiptap.

```tsx-live-prose-noinline
function CallToActionView({ node }) {
  return (
    <NodeViewWrapper className='grid justify-items-start'>
      <Button intent='brand' emphasis='strong'>
        {String(node.attrs.label)}
      </Button>
    </NodeViewWrapper>
  )
}

const callToAction = {
  label: 'Call to action',
  icon: TicketIcon,
  keywords: ['button'],
  settings: [
    { name: 'label', label: 'Button', type: 'text' },
    { name: 'href', label: 'Link', type: 'text', helperText: 'A page on this site, such as /events.' }
  ],
  node: Node.create({
    name: 'callToAction',
    group: 'block',
    atom: true,
    addAttributes: () => ({
      label: { default: 'Get tickets' },
      href: { default: '/events/ochre-kite-weekender' }
    }),
    renderHTML: ({ HTMLAttributes }) => ['div', mergeAttributes(HTMLAttributes)],
    addNodeView: () => reactNodeView(CallToActionView)
  })
}

// Stored attrs are untrusted, so the link is kept only when it's a site path.
const sitePath = (href) =>
  typeof href === 'string' && /^\/(?!\/)/.test(href) ? href : undefined

const nodeMapping = {
  callToAction: ({ attrs }) => (
    <Button href={sitePath(attrs.href)} intent='brand' emphasis='strong'>
      {String(attrs.label)}
    </Button>
  )
}

function Page() {
  const [value, setValue] = useState({
    version: 1,
    preset: 'blocks',
    doc: {
      type: 'doc',
      content: [
        { type: 'heading', attrs: { level: 2 }, content: [{ type: 'text', text: 'Ochre Kite Weekender' }] },
        { type: 'callToAction', attrs: { label: 'Get tickets', href: '/events/ochre-kite-weekender' } },
        { type: 'paragraph' }
      ]
    }
  })
  return (
    <>
      <Editor
        aria-label='Page'
        extensions={[callToAction]}
        value={value}
        onValueChange={setValue}
      />
      {renderEditorValue(value, { nodeMapping })}
    </>
  )
}

render(<Page />)
```

## Accessibility

- In the blocks preset, `/` opens a `listbox` named Insert under the caret.
  Focus stays in the text, which points `aria-activedescendant` at the active
  option and `aria-controls` at the list.
- The grip and its menu, with their keys, are under
  [Block handle](#block-handle).

| Keys | Action |
| --- | --- |
| `/` | Open the insert menu, in the blocks preset |
| `Enter` | With a block that has settings selected, open them |
| `Escape` | In a block's settings, keep the changes and close them |

Every preset's other keys are on the [Editor](/components/editor#accessibility)
page.
