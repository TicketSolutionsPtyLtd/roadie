A list of records to search, filter, sort, and page through.

## Import

```tsx
import { RecordList, listLayout } from '@oztix/roadie-components/record-list'
import { Records, useRecords } from '@oztix/roadie-components/records'
import { recordFields } from '@oztix/roadie-core/records'
```

Row parts can hold a `cell` function, as can fields with a `match`, `getRowId`, and the `useRecords` instance, so render the records in a client component, a file that starts with `'use client'`.

## Examples

### Default

`RecordList` shows records as rows, with the toolbar, pagination, status, and bulk actions built in. It takes the same options as `useRecords`, and in `row` the field each part of a row shows.

```tsx-live-noinline
const field = recordFields()
const fields = [
  field.text('name', { label: 'Venue' }),
  field.location('location', { label: 'Location' }),
  field.number('capacity', { label: 'Capacity' }),
  field.number('events', { label: 'Events this year' })
]
const venues = [
  { id: 'kazoo', name: 'Kazoo Hollow Room', location: 'Brisbane', capacity: 450, events: 82 },
  { id: 'antler', name: 'Antler Kettle Hall', location: 'Melbourne', capacity: 1200, events: 64 },
  { id: 'echidna', name: 'Echidna Gaslight Theatre', location: 'Sydney', capacity: 900, events: 71 },
  { id: 'foxglove', name: 'Foxglove Tin Pavilion', location: 'Perth', capacity: 2400, events: null }
]

render(
  <RecordList
    caption='Venues'
    data={venues}
    fields={fields}
    getRowId={(row) => row.id}
    recordName={{ one: 'venue', other: 'venues' }}
    row={{
      leading: { key: 'name', cell: ({ row }) => <Avatar size='sm' name={row.name} /> },
      title: 'name',
      description: 'location',
      details: ['capacity', 'events']
    }}
  />
)
```

### Row parts and layouts

`row`, or a `listLayout` given to `Records`, names the field each part of a row shows: `title` names the record and carries its `getRowHref` link, `description` sits under it, `leading` before it, such as an avatar, and `trailing` at the row's end. `details` follow the description on its line, in order, each after a dot, and a detail with no value is left out. The line truncates at the row's end, so keep it to one or two. A part is a field's key, or `{ key, cell }` to replace how the value shows, and a status field shows a `Badge`. Rows look the same at every width, as a table's do on a phone.

Beside a table or grid, Configure shows a Layout switcher above the sort, and the view's `layout` becomes `{ type: 'list' }`, which the URL keeps as `layout=list`. Configure lists the row's details as it does a grid's [card fields](/components/record-grid#card-fields): drag to reorder, and the eye shows or hides one. They write the view's `layout.fields`, left out once back to the list's `details`.

```tsx-live-noinline-expand
const venues = ['Kazoo Hollow Room', 'Antler Kettle Hall', 'Echidna Gaslight Theatre', 'Foxglove Tin Pavilion']
const names = ['Marzipan Thunderclap', 'Ember Galah Ball', 'Nectarine Hoedown', 'Tuxedo Possum Cabaret', 'Lampshade Disco']
const statuses = ['on-sale', 'selling-fast', 'sold-out']
const events = Array.from({ length: 18 }, (_, index) => ({
  id: `event-${index}`,
  name: `${names[index % names.length]} ${Math.floor(index / names.length) + 1}`,
  venue: venues[index % venues.length],
  status: statuses[index % statuses.length],
  sold: (index * 37) % 2400
}))

const field = recordFields()
const fields = [
  field.text('name', { label: 'Event' }),
  field.text('venue', { label: 'Venue' }),
  field.option('status', {
    label: 'Status',
    status: {
      'on-sale': { intent: 'success', label: 'On sale' },
      'selling-fast': { intent: 'warning', label: 'Selling fast' },
      'sold-out': { intent: 'neutral', label: 'Sold out' }
    }
  }),
  field.number('sold', { label: 'Sold' })
]
const column = tableColumns(fields)
const layouts = [
  listLayout({ title: 'name', description: 'venue', trailing: 'status', details: ['sold'] }),
  tableLayout([column.field('name', { pin: true }), column.field('venue'), column.field('status'), column.field('sold')])
]

function Events() {
  const [view, setView] = useState({ query: { search: '', filters: [], sort: [] }, layout: { type: 'list' } })
  const records = useRecords({
    data: events,
    fields,
    getRowId: (row) => row.id,
    getRowHref: (row) => `#${row.id}`,
    recordName: { one: 'event', other: 'events' },
    view,
    onViewChange: setView
  })
  return (
    <div className='grid gap-3'>
      <p className='text-sm text-subtle'>URL: ?{recordViewToSearchParams(view).toString()}</p>
      <Records records={records} layouts={layouts} caption='Events'>
        <Records.Header />
        <Records.Content />
        <Records.Pagination />
        <Records.Status />
      </Records>
    </div>
  )
}

render(<Events />)
```

### Grouped

A view's `layout.groupBy` groups the rows by up to three fields with options, such as a status, outermost first, under a title and count per option, in the options' order. Each field after the first groups the rows inside each group before it. Records with no value follow in a "No" group, such as "No status", and an option with no records is left out. Inside a group, rows keep the view's sort. The URL keeps it as `groupBy=status,venue`. To group a list by default, set it in `defaultView` or the saved view, so people can always turn it off. A field that holds a list, or has no options, can't group. People pick the field, or None, from Group by in the list's settings, then a field to group inside it from Then by, and a third from And then by, and changing the row's details keeps the grouping. Group by is left out when no field can group, or when the list loads by range.

Each group's title opens and closes it, and a collapsed group keeps its title and count. That's for the session: it isn't saved in the view or the URL. Give a field `groupHeading` for content under its groups' titles, such as a venue's suburb or a milestone's dates and links, wherever the field groups and at any level. It gets the group's `value`, `label` and `count`.

Grouping applies to one page of rows at a time, so a group can continue on the next page, and a grouped list renders every row on its page rather than only those near the screen. A list that loads by range stays ungrouped. A Shift range in Select mode follows the order on screen, across groups.

```tsx-live-noinline-expand
const events = [
  ['Marzipan Thunderclap', 'Kazoo Hollow Room', 'on-sale'],
  ['Ember Galah Ball', 'Antler Kettle Hall', 'sold-out'],
  ['Nectarine Hoedown', 'Echidna Gaslight Theatre', 'on-sale'],
  ['Tuxedo Possum Cabaret', 'Kazoo Hollow Room', 'selling-fast'],
  ['Lampshade Disco', 'Antler Kettle Hall', null]
].map(([name, venue, status], index) => ({ id: `event-${index}`, name, venue, status }))

const suburbs = {
  'Kazoo Hollow Room': 'Fitzroy',
  'Antler Kettle Hall': 'Brunswick',
  'Echidna Gaslight Theatre': 'Collingwood'
}

const field = recordFields()
const fields = [
  field.text('name', { label: 'Event' }),
  {
    ...field.option('venue', {
      label: 'Venue',
      options: ['Kazoo Hollow Room', 'Antler Kettle Hall', 'Echidna Gaslight Theatre'].map(
        (venue) => ({ value: venue, label: venue })
      )
    }),
    groupHeading: ({ value }) => suburbs[value] ?? null
  },
  field.option('status', {
    label: 'Status',
    status: {
      'on-sale': { intent: 'success', label: 'On sale' },
      'selling-fast': { intent: 'warning', label: 'Selling fast' },
      'sold-out': { intent: 'neutral', label: 'Sold out' }
    }
  })
]
const layouts = [listLayout({ title: 'name', description: 'venue', trailing: 'status' })]

function Events() {
  const records = useRecords({
    data: events,
    fields,
    getRowId: (row) => row.id,
    getRowHref: (row) => `#${row.id}`,
    recordName: { one: 'event', other: 'events' },
    selectable: true,
    defaultView: { layout: { type: 'list', groupBy: ['status', 'venue'] } }
  })
  return (
    <Records records={records} layouts={layouts} caption='Events by status and venue'>
      <Records.Header />
      <Records.Content />
    </Records>
  )
}

render(<Events />)
```

### States, selection, and long lists

These work as they do in the grid. `loading` shows placeholder rows, `error` replaces the rows, and the empty state offers to clear the search and filters; see [States](/components/record-grid#states). Rows have no checkboxes, so selectable records in a list offer Select mode, with the bulk actions floating at the foot of the screen; see [Selection and actions](/components/record-grid#selection-and-actions). Past 100 records on a page the list renders only the rows near the screen, and with a `loadRange` it loads records by range; see [Long lists](/components/record-grid#long-lists).

## Accessibility

- `caption` names the rows: they are a list named by the caption, each row an item with its place in the whole list (`aria-posinset` and `aria-setsize`) when the list holds only some of them, such as a page of several or more than 100 rows.
- A row's title is its name. With `getRowHref` it is a link, and the whole row takes its hover and press; it opens in a new tab with Cmd or Ctrl, like any link.
- In Select mode, each row's checkbox is named "Select" and the row's title, and covers the row, so a tap anywhere on it toggles, and the link steps aside. Escape leaves Select mode, and focus lands on Select.
- The Configure button is named "Configure list", as is the dialog it opens. Each shown detail's handle is named "Reorder" and the field, and its eye is a toggle button named "Show" and the field.
- Grouped, the rows are a list named by the caption holding a list per group, each named by its title and count, such as "On sale 4". Titles are `h2` headings, with `h3` and `h4` for the second and third levels, each level's groups a list inside its group. The first two levels are headings, the outer one larger, and outer groups part with a rule, the same however many levels follow; a third level keeps the quieter group title.
- Each group's title is a button inside its heading that opens and closes the group, with `aria-expanded`, named by its title and count. Content from `groupHeading` follows the heading.
- The Group by selects are labelled "Group by", "Then by", and "And then by". Each appears once the one before it holds a field.
- `Records.Status` announces Loading, the error, the result count, and the selection.
