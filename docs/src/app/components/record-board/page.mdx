A board of records in a column per status, with cards moved between them.

## Import

```tsx
import { boardLayout } from '@oztix/roadie-components/record-board'
import { Records, useRecords } from '@oztix/roadie-components/records'
import { recordFields } from '@oztix/roadie-core/records'
```

Fields can hold functions, as can `getRowId`, `onMove` and the `useRecords` instance, so render the board in a client component, a file that starts with `'use client'`.

## Examples

### Default

Give `Records` a `boardLayout`, naming the option field in `groupBy` and the fields each card shows, as a grid's cards take them. Each option of the field is a column, in option order, and records with no value sit in a last column named for the field, such as "No status". Drag a card by its handle to another column, or pick "Move to" from the handle's menu. `onMove` gets the record and the grouping fields the move changed, such as `{ status: 'sold_out' }`, with null for that last column. Save them as a patch and update your data; until then the card shows in its new column.

```tsx-live-noinline-expand
const names = ['Marzipan Thunderclap', 'Ember Galah Ball', 'Nectarine Hoedown', 'Tuxedo Possum Cabaret', 'Lampshade Disco']
const initial = names.map((name, index) => ({
  id: `event-${index}`,
  name,
  venue: ['Kazoo Hollow Room', 'Antler Kettle Hall', 'Drongo Bell Social Club'][index % 3],
  status: ['draft', 'on_sale', 'on_sale', 'sold_out', ''][index]
}))

const field = recordFields()
const fields = [
  field.text('name', { label: 'Event' }),
  field.text('venue', { label: 'Venue' }),
  field.option('status', {
    label: 'Status',
    status: {
      draft: { intent: 'neutral' },
      on_sale: { intent: 'success' },
      sold_out: { intent: 'danger' }
    }
  })
]

function Events() {
  const [events, setEvents] = useState(initial)
  const [layouts] = useState(() => [
    boardLayout({
      groupBy: 'status',
      title: 'name',
      description: 'venue',
      // Changes name each field the move set, such as { status: 'sold_out' }; null is "No status".
      onMove: (event, changes) =>
        setEvents((all) =>
          all.map((row) =>
            row.id === event.id && 'status' in changes
              ? { ...row, status: changes.status ?? '' }
              : row
          )
        )
    })
  ])
  const records = useRecords({
    data: events,
    fields,
    getRowId: (row) => row.id,
    getRowHref: (row) => `#${row.id}`,
    recordName: { one: 'event', other: 'events' }
  })
  return (
    <Records records={records} layouts={layouts} caption='Events'>
      <Records.Header />
      <Records.Content />
      <Records.Status />
    </Records>
  )
}

render(<Events />)
```

### Lanes

Give `groupBy` two fields, and the second makes a lane across the columns for each of its options, in option order, then one for records with no value, such as "No milestone". Every lane shows, even with no cards, so there's always somewhere to move a card. The column headers stay in view as the lanes scroll, and each counts its column across every lane. A lane's title opens and closes it for the session; it isn't saved in the view or the URL. Give the lane field `groupHeading` for content under each lane's title, such as a milestone's dates. Cards move between columns within their lane, and `onMove` gets only the column's field.

```tsx-live-noinline-expand
const stories = [
  ['Search shows near me', 'find', 'pilot'],
  ['Save a show for later', 'find', 'later'],
  ['Pick seats on a map', 'buy', 'launch'],
  ['Pay with a saved card', 'buy', 'pilot'],
  ['Split tickets with friends', 'buy', 'later'],
  ['Show my ticket at the door', 'attend', 'pilot'],
  ['Add the show to my calendar', 'attend', 'launch']
].map(([story, activity, milestone], index) => ({ id: `story-${index}`, story, activity, milestone }))

const dates = { pilot: 'Out 3 March', launch: 'Out 14 April' }

const field = recordFields()
const fields = [
  field.text('story', { label: 'Story' }),
  field.option('activity', {
    label: 'Activity',
    options: [
      { value: 'find', label: 'Find a show' },
      { value: 'buy', label: 'Buy tickets' },
      { value: 'attend', label: 'Go to the show' }
    ]
  }),
  {
    ...field.option('milestone', {
      label: 'Milestone',
      options: [
        { value: 'pilot', label: 'Pilot' },
        { value: 'launch', label: 'Launch' },
        { value: 'later', label: 'Later' }
      ]
    }),
    groupHeading: ({ value }) => dates[value] ?? null
  }
]

function StoryMap() {
  const [data, setData] = useState(stories)
  const [layouts] = useState(() => [
    boardLayout({
      // Columns by activity, then a lane per milestone.
      groupBy: ['activity', 'milestone'],
      title: 'story',
      onMove: (story, changes) =>
        setData((all) => all.map((row) => (row.id === story.id ? { ...row, ...changes } : row)))
    })
  ])
  const records = useRecords({ data, fields, getRowId: (row) => row.id, recordName: { one: 'story', other: 'stories' } })
  return (
    <Records records={records} layouts={layouts} caption='Story map'>
      <Records.Content />
    </Records>
  )
}

render(<StoryMap />)
```

A view's `groupBy` wins over the layout's, so a view grouped by one field draws no lanes. A third level stays in the view for other layouts, but the board doesn't draw it.

### Moves the app turns down

Return a promise from `onMove` while you save. Reject it with an `Error` whose message people can read, and the card goes back to its column with that message above the board. Without `onMove`, cards have no handle and don't move.

```tsx
boardLayout({
  groupBy: 'status',
  title: 'name',
  onMove: async (event, changes) => {
    if (event.status === 'cancelled') throw new Error('A cancelled event can’t go back on sale.')
    await saveEvent(event.id, changes)
  }
})
```

### Layouts

Give `Records` a `boardLayout` beside the table, and people switch between them from View. A saved view holds `{ type: 'board', groupBy: ['status'] }`, so a view can make its columns from another option field. Switching to the board uses the layout's own `groupBy` until a view picks one. A field that holds a list, or has no options, can't make columns, and `validateRecordView` reports it.

```tsx
const layouts = [
  tableLayout(columns),
  boardLayout({ groupBy: 'status', title: 'name', onMove })
]
```

### On a phone

The columns sit in a row that scrolls sideways, each about 85% of the width, so the next column peeks in. A card dragged to the edge of the screen drops into the column there; the Move menu reaches every column. With lanes, the columns and their headers scroll sideways together, each lane a section inside every column, and lane titles stay at the start of the screen.

### Column counts

Each column and lane counts the records loaded into it. With a server, that's the page in view, not every match.

    Make the columns from a short set of stages, such as draft, on sale and

  </Guideline.Do>

    Don't make a column per venue or person. Dozens of columns scroll out of

## Accessibility

- The board is a group named by the records' caption, holding a region for each column, named by its option.
- With lanes, the board holds a region for each lane instead, named by its option. Its title is a heading inside the `summary` of a `details` element, so it opens and closes the lane and is announced as expanded or collapsed. Inside, each column's cards are a group named by the column. The column headers above the lanes are hidden from screen readers, since each group names its column.
- Each card's handle opens a Move menu on click, Enter or Space. An item such as "Move Marzipan Thunderclap to Sold out" moves the card to that column, where it takes its place in the view's sort, and focus follows it. With lanes, the menu lists the columns in the card's lane.
- The column a card joins announces the move. A rejected move shows its message in an alert.
- Each card's title links to its record through `getRowHref`.
