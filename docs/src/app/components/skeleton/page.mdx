# Skeleton

A placeholder that holds the space content will occupy while it loads.

## Import

```tsx
import { Skeleton } from '@oztix/roadie-components/skeleton'
```

## Examples

### Default

One text line, as tall as the line height it inherits.

```tsx-live
<Skeleton />
```

### Shapes

`text` is a line of copy, `block` is a panel such as an image or a card body, and `circle` is an avatar. Width and height come from Tailwind utilities, so the shape only sets the radius and a starting size.

```tsx-live
<div className='grid gap-4'>
  <Skeleton shape='text' />
  <Skeleton shape='block' />
  <Skeleton shape='circle' />
</div>
```

### Sizes

Size a Skeleton the way you would size the content it stands in for. A `text` line tracks the type size around it, so put it in an element that carries the type class. Skeleton renders a `div`, so that element cannot be the `p` it stands in for.

```tsx-live
<div className='grid gap-4'>
  <div className='text-sm'><Skeleton /></div>
  <div className='text-lg'><Skeleton className='w-2/3' /></div>
  <Skeleton shape='block' className='h-40' />
  <Skeleton shape='circle' className='size-16' />
</div>
```

### Emphasis

`subtle` is the default. Use `subtler` on a raised or sunken surface where the default fill reads too loud.

```tsx-live
<div className='grid gap-4'>
  <Skeleton emphasis='subtle' />
  <Skeleton emphasis='subtler' />
</div>
```

### Intents

Skeleton takes its intent from context, so a placeholder inside a tinted region picks up that palette. Pass `intent` to set it directly.

```tsx-live
<div className='grid gap-4'>
  <Skeleton />
  <Skeleton intent='brand' />
  <Skeleton intent='accent' />
  <Skeleton intent='danger' />
</div>
```

### Composition

A paragraph is several text lines in a grid, with a short last line.

```tsx-live
<div className='grid gap-2'>
  <Skeleton />
  <Skeleton />
  <Skeleton className='w-3/5' />
</div>
```

A list row is a circle beside a two-line stack.

```tsx-live
<div className='grid gap-4'>
  {[0, 1, 2].map((row) => (
    <div key={row} className='flex items-center gap-3'>
      <Skeleton shape='circle' />
      <div className='grid flex-1 gap-2'>
        <Skeleton className='w-1/3' />
        <Skeleton className='w-2/3' />
      </div>
    </div>
  ))}
</div>
```

## Guidelines

Use a Skeleton once the page is on screen and its content is still arriving, such as an event list still fetching. For a full page that has not rendered yet, show nothing rather than a screen of grey bars.

Match the real layout. The skeleton should occupy the same box as the content that replaces it, so nothing jumps when the data lands.

Use a fixed number of rows, three or four, when the real count is unknown. A skeleton per expected record makes the wait look longer than it is.

Stop at one level of detail. A card skeleton is an image block, a title line and a meta line, not every element the card will eventually hold.

Skeletons that mount together sweep together. There is no per-element delay, on purpose: a staggered set reads as a row of separate things blinking, while a synchronised sweep reads as one surface waiting. A skeleton added later, such as a row appended to a list, joins out of phase and settles into the same tempo.

## Accessibility

The root carries `aria-hidden='true'`, so a screen reader reads nothing from the placeholder itself. A row of announced bars would be noise, and the shapes carry no information.

The region that owns the fetch announces the wait. Put `aria-busy='true'` on it while the request is in flight, and add a small live region that carries the wording. `aria-busy` alone changes no announcement, so without the live region a screen reader user hears nothing until they navigate back to the section.

```tsx
<section aria-busy={isPending} aria-labelledby='events-heading'>
  <h2 id='events-heading' className='text-display-ui-4 text-strong'>
    Upcoming events
  </h2>
  <p role='status' className='sr-only'>
    {isPending ? 'Loading events' : `${events.length} events loaded`}
  </p>
  {isPending ? <Skeleton shape='block' /> : <EventList events={events} />}
</section>
```

Keep the live region small and separate from the content it describes. A `role='status'` on the whole section would read the entire result back once it lands.

The motion runs on the `animate-shimmer` utility from the motion tokens: a tint pulse on `--duration-ambient` with a highlight sweeping across on `--duration-sweep`. Under `prefers-reduced-motion: reduce` the sweep is removed and the global motion reset cuts the pulse to a single pass, so the placeholder holds a static tint and never flickers.
