A row of buttons, toggles, links and menus that takes one Tab stop.

## Import

```tsx
import { Toolbar } from '@oztix/roadie-components/toolbar'
```

## Examples

### Default

Each part renders a Roadie component you already know. `Toolbar.Button` is a `Button` at `emphasis='subtler'`, and the toolbar sits in a normal surface, a pill that hugs its items, so a row of buttons reads as one control.

```tsx-live
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
  <Toolbar.Separator />
  <Toolbar.Button>Save draft</Toolbar.Button>
</Toolbar>
```

### Sizes

`size` sets the buttons and links the toolbar renders, using the `Button` sizes.

```tsx-live layout=stack
{/* Small */}
<Toolbar size='sm' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Medium */}
<Toolbar size='md' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Large */}
<Toolbar size='lg' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### Emphasis

`emphasis` sets the surface behind the toolbar: `normal` by default, `subtle`, `raised` or `floating` over other content, and `subtler` for none, when the toolbar sits inside another surface such as a `Card`. The buttons stay at `subtler` on every surface.

```tsx-live layout=stack
{/* Normal */}
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Subtle */}
<Toolbar emphasis='subtle' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Raised */}
<Toolbar emphasis='raised' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Floating */}
<Toolbar emphasis='floating' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Subtler */}
<Toolbar emphasis='subtler' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### States

A disabled `Toolbar.Button` stays in the arrow order, so a keyboard user still finds it. `disabled` on `Toolbar.Group` or on the toolbar disables every `Toolbar.Button` and `ToggleGroup` inside it; a disabled `ToggleGroup`'s items leave the arrow order. A `Toolbar.Link` stays active, so remove it when it shouldn't be followed.

```tsx-live layout=stack
{/* One button disabled */}
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button disabled>Redo</Toolbar.Button>
</Toolbar>
{/* Disabled */}
<Toolbar aria-label='History' disabled>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### Composition

#### Formatting toolbar

Pass a `Toggle` or an `IconButton` to `Toolbar.Button` with `render`. A `ToggleGroup` joins the arrow order as it is. Pass `Toolbar.Button` to `Menu.Trigger` with `render` to open a menu.

```tsx-live
<Toolbar aria-label='Formatting'>
  <Toolbar.Group aria-label='Text style'>
    <Toolbar.Button render={<Toggle emphasis='subtler' aria-label='Bold'><TextBIcon weight='bold' className='size-4' /></Toggle>} />
    <Toolbar.Button render={<Toggle emphasis='subtler' aria-label='Italic'><TextItalicIcon weight='bold' className='size-4' /></Toggle>} />
  </Toolbar.Group>
  <Toolbar.Separator />
  <ToggleGroup emphasis='subtler' aria-label='Alignment' defaultValue={['left']}>
    <ToggleGroup.Item value='left' aria-label='Align left'><TextAlignLeftIcon weight='bold' className='size-4' /></ToggleGroup.Item>
    <ToggleGroup.Item value='center' aria-label='Align centre'><TextAlignCenterIcon weight='bold' className='size-4' /></ToggleGroup.Item>
    <ToggleGroup.Item value='right' aria-label='Align right'><TextAlignRightIcon weight='bold' className='size-4' /></ToggleGroup.Item>
  </ToggleGroup>
  <Toolbar.Separator />
  <Menu>
    <Menu.Trigger render={<Toolbar.Button><PlusIcon weight='bold' className='size-4' />Insert<CaretDownIcon weight='bold' className='size-4' /></Toolbar.Button>} />
    <Menu.Content>
      <Menu.Item icon={<ImageIcon weight='bold' />}>Image</Menu.Item>
      <Menu.Item icon={<TableIcon weight='bold' />}>Table</Menu.Item>
      <Menu.Item icon={<LinkSimpleIcon weight='bold' />}>Link</Menu.Item>
    </Menu.Content>
  </Menu>
</Toolbar>
```

A `render` element keeps its own props, so the toolbar's `size` doesn't reach it. Set `size` on the `Toggle`, `IconButton` or `ToggleGroup` to match.

#### Links

`Toolbar.Link` takes an `href`, which routes through the Link given to `RoadieProvider`. An external `href` opens in a new tab.

```tsx-live
<Toolbar aria-label='Event'>
  <Toolbar.Button>Save draft</Toolbar.Button>
  <Toolbar.Link href='/events/feathered-anchor-sessions'>Preview</Toolbar.Link>
</Toolbar>
```

#### Vertical

With `orientation='vertical'` the items stack in a column as wide as the widest, and separators run across it.

```tsx-live
<Toolbar orientation='vertical' aria-label='Formatting'>
  <Toolbar.Button render={<Toggle emphasis='subtler' aria-label='Bold'><TextBIcon weight='bold' className='size-4' /></Toggle>} />
  <Toolbar.Button render={<Toggle emphasis='subtler' aria-label='Italic'><TextItalicIcon weight='bold' className='size-4' /></Toggle>} />
  <Toolbar.Button render={<Toggle emphasis='subtler' aria-label='Underline'><TextUnderlineIcon weight='bold' className='size-4' /></Toggle>} />
  <Toolbar.Separator />
  <Toolbar.Button render={<IconButton emphasis='subtler' aria-label='Undo'><ArrowCounterClockwiseIcon weight='bold' className='size-4' /></IconButton>} />
  <Toolbar.Button render={<IconButton emphasis='subtler' aria-label='Redo'><ArrowClockwiseIcon weight='bold' className='size-4' /></IconButton>} />
</Toolbar>
```

#### When space runs out

On a touch screen, or a screen narrower than `md`, the items stay on one row and scroll sideways, with the edges fading while there's more to see. Elsewhere they wrap onto new lines, and the pill becomes a rounded box. Arrow keys scroll the focused item into view either way.

```tsx-live width=72
<Toolbar aria-label='Event'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
  <Toolbar.Separator />
  <Toolbar.Button>Duplicate</Toolbar.Button>
  <Toolbar.Button>Save draft</Toolbar.Button>
  <Toolbar.Button>Schedule</Toolbar.Button>
  <Toolbar.Link href='/events/feathered-anchor-sessions'>Preview</Toolbar.Link>
</Toolbar>
```

## Guidelines

- **Group related controls.** Put controls that work together, such as text styles, in a `Toolbar.Group` and separate the groups with `Toolbar.Separator`.
- **Drop the surface inside another one.** Inside a `Card`, a pane header, or a bar that already has a surface, use `emphasis='subtler'` so the toolbar doesn't draw a box within a box. Use `floating` for a toolbar over content, such as on an image.
- **Keep the toolbar short.** On a phone the row scrolls, so actions past the edge are out of sight until someone scrolls. Put the most used first, and rarely used actions in a `Menu`.
- **Size it with `className` or `style`.** Both go on the surface, the toolbar's outermost element, so margins and widths set there place the whole toolbar.
- **Use `Toggle` for an on and off state.** A `Toggle` reports whether it's pressed; a `Button` only runs an action.
- **Label every icon-only control,** and the toolbar itself.

## Accessibility

- Renders `role='toolbar'` with `aria-orientation`. Give it an `aria-label`, or point `aria-labelledby` at a visible heading.
- **Keyboard:** `Tab` moves into the toolbar and out again in one stop. Arrow keys move between items (`ArrowLeft` and `ArrowRight`, or `ArrowUp` and `ArrowDown` when vertical). Focus wraps from the last item to the first unless `loopFocus` is `false`.
- A disabled `Toolbar.Button` keeps focus, with `aria-disabled`, so a screen reader still announces it.
- `Toolbar.Separator` renders `role='separator'`, running across the toolbar.
