A row of buttons, toggles, links, and menus that takes one Tab stop.

## Import

```tsx
import { Toolbar } from '@oztix/roadie-components/toolbar'
```

## Examples

### Default

Each part renders a Roadie component you already know. `Toolbar.Button` is a `Button` at `emphasis='subtler'`, and the toolbar sits in a normal surface, a pill that hugs its items, so a row of buttons reads as one control.

```tsx-live
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
  <Toolbar.Separator />
  <Toolbar.Button>Save draft</Toolbar.Button>
</Toolbar>
```

### Sizes

`size` sets the buttons and links the toolbar renders, using the `Button` sizes.

```tsx-live layout=stack
{/* Small */}
<Toolbar size='sm' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Medium */}
<Toolbar size='md' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Large */}
<Toolbar size='lg' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### Emphasis

`emphasis` sets the surface behind the toolbar: `normal` by default, `subtle`, `raised` or `floating` for a toolbar over other content, and `subtler` for none, when the toolbar sits inside another surface such as a `Card`. The buttons stay at `subtler` on every surface.

```tsx-live layout=stack
{/* Normal */}
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Subtle */}
<Toolbar emphasis='subtle' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Raised */}
<Toolbar emphasis='raised' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Floating */}
<Toolbar emphasis='floating' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
{/* Subtler */}
<Toolbar emphasis='subtler' aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### Flush

`flush` drops the border, shadow, and pill shape, for a bar docked along an edge, such as across the top of an editor or a panel. The controls keep the same inset as any toolbar, so a hover never meets the edge. `emphasis` sets only its fill. Draw the edge on the parent, clip its corners with `overflow-clip`, and add `w-full` to run the bar across it.

```tsx-live
<div className='grid min-w-0 overflow-clip rounded-xl border border-subtle'>
  <Toolbar flush emphasis='subtler' size='sm' aria-label='History' className='w-full border-b border-subtler'>
    <Toolbar.Button>Undo</Toolbar.Button>
    <Toolbar.Button>Redo</Toolbar.Button>
    <Toolbar.Separator />
    <Toolbar.Button>Save draft</Toolbar.Button>
  </Toolbar>
  <p className='p-3 text-subtle'>Doors open 7pm at the Kazoo Hollow Room.</p>
</div>
```

### States

A disabled `Toolbar.Button` stays in the arrow order, so a keyboard user still finds it. `disabled` on `Toolbar.Group`, `Toolbar.ToggleGroup`, or the toolbar disables every item inside it, and they stay in the arrow order too. A `Toolbar.Button` with an `href` takes its own `disabled`, which keeps it in the arrow order and stops the click, but a disabled group or toolbar leaves it active. Disable it too, or remove it, when it shouldn't be followed.

```tsx-live layout=stack
{/* One button disabled */}
<Toolbar aria-label='History'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button disabled>Redo</Toolbar.Button>
</Toolbar>
{/* Disabled */}
<Toolbar aria-label='History' disabled>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
</Toolbar>
```

### Composition

#### Formatting toolbar

`Toolbar.Toggle` is a `Toggle` at the toolbar's size that turns a setting on and off. Toggles in a `Toolbar.ToggleGroup` share one value: give each a `value`, and one is pressed at a time, or several with `multiple`. A `Toolbar.Button` whose only child is an icon renders square, as an `IconButton`, so give it an `aria-label`. Pass `Toolbar.Button` to `Menu.Trigger` with `render` to open a menu.

```tsx-live
<Toolbar aria-label='Formatting'>
  <Toolbar.Group aria-label='Text style'>
    <Toolbar.Toggle aria-label='Bold'><TextBIcon weight='bold' className='size-4' /></Toolbar.Toggle>
    <Toolbar.Toggle aria-label='Italic'><TextItalicIcon weight='bold' className='size-4' /></Toolbar.Toggle>
  </Toolbar.Group>
  <Toolbar.Separator />
  <Toolbar.ToggleGroup aria-label='Alignment' defaultValue={['left']}>
    <Toolbar.Toggle value='left' aria-label='Align left'><TextAlignLeftIcon weight='bold' className='size-4' /></Toolbar.Toggle>
    <Toolbar.Toggle value='center' aria-label='Align centre'><TextAlignCenterIcon weight='bold' className='size-4' /></Toolbar.Toggle>
    <Toolbar.Toggle value='right' aria-label='Align right'><TextAlignRightIcon weight='bold' className='size-4' /></Toolbar.Toggle>
  </Toolbar.ToggleGroup>
  <Toolbar.Separator />
  <Menu>
    <Menu.Trigger render={<Toolbar.Button><PlusIcon weight='bold' className='size-4' />Insert<CaretDownIcon weight='bold' className='size-4' /></Toolbar.Button>} />
    <Menu.Content>
      <Menu.Item icon={<ImageIcon weight='bold' />}>Image</Menu.Item>
      <Menu.Item icon={<TableIcon weight='bold' />}>Table</Menu.Item>
      <Menu.Item icon={<LinkSimpleIcon weight='bold' />}>Link</Menu.Item>
    </Menu.Content>
  </Menu>
</Toolbar>
```

Every part takes the toolbar's `size`. Anything passed to `render` keeps its own props instead, so set `size` on it to match. With one value pressed at a time, a `Toolbar.ToggleGroup`'s fill slides from toggle to toggle, as in `ToggleGroup`; with `multiple`, each pressed toggle fills itself. Use it here rather than `ToggleGroup`, whose own track and smaller items wouldn't match the toolbar.

#### Links

Give `Toolbar.Button` an `href` and it renders a link, as `Button` does: an internal `href` routes through the Link given to `RoadieProvider`, and an external one opens in a new tab. It stays in the arrow order with the buttons.

```tsx-live
<Toolbar aria-label='Event'>
  <Toolbar.Button>Save draft</Toolbar.Button>
  <Toolbar.Button href='/events/feathered-anchor-sessions'>Preview</Toolbar.Button>
</Toolbar>
```

#### Vertical

With `orientation='vertical'` the items stack in a column as wide as the widest, and separators run across it.

```tsx-live
<Toolbar orientation='vertical' aria-label='Formatting'>
  <Toolbar.Toggle aria-label='Bold'><TextBIcon weight='bold' className='size-4' /></Toolbar.Toggle>
  <Toolbar.Toggle aria-label='Italic'><TextItalicIcon weight='bold' className='size-4' /></Toolbar.Toggle>
  <Toolbar.Toggle aria-label='Underline'><TextUnderlineIcon weight='bold' className='size-4' /></Toolbar.Toggle>
  <Toolbar.Separator />
  <Toolbar.Button aria-label='Undo'><ArrowCounterClockwiseIcon weight='bold' className='size-4' /></Toolbar.Button>
  <Toolbar.Button aria-label='Redo'><ArrowClockwiseIcon weight='bold' className='size-4' /></Toolbar.Button>
</Toolbar>
```

#### When space runs out

On a touch screen, or a screen narrower than `md`, the items stay on one row and scroll sideways, with the edges fading while there's more to see. Elsewhere they wrap onto new lines, and the pill becomes a rounded box. Arrow keys scroll the focused item into view either way.

```tsx-live width=72
<Toolbar aria-label='Event'>
  <Toolbar.Button>Undo</Toolbar.Button>
  <Toolbar.Button>Redo</Toolbar.Button>
  <Toolbar.Separator />
  <Toolbar.Button>Duplicate</Toolbar.Button>
  <Toolbar.Button>Save draft</Toolbar.Button>
  <Toolbar.Button>Schedule</Toolbar.Button>
  <Toolbar.Button href='/events/feathered-anchor-sessions'>Preview</Toolbar.Button>
</Toolbar>
```

## Guidelines

- **Group related controls.** Put controls that work together, such as text styles, in a `Toolbar.Group` and separate the groups with `Toolbar.Separator`.
- **Dock a bar with `flush`.** Along the edge of a card, pane, or editor, a flush toolbar lines up with the edge and the parent draws the divider.
- **Drop the surface inside another one.** Inside a `Card`, a pane header, or a bar that already has a surface, use `emphasis='subtler'` so the toolbar doesn't draw a box within a box. Use `floating` for a toolbar over content, such as on an image.
- **Keep the toolbar short.** On a phone the row scrolls, so actions past the edge are out of sight until someone scrolls. Put the most used first, and rarely used actions in a `Menu`.
- **Size it with `className` or `style`.** Both go on the surface, the toolbar's outermost element. It's at most as wide as its container, so space it with the container's padding or `gap` rather than a margin, which pushes a full-width toolbar past the edge.
- **Let its container shrink.** On a phone the toolbar's row is as wide as all its items. A grid or flex item holding it, such as a form control in a `Field`, grows to fit unless it has `min-w-0`.
- **Use `Toolbar.Toggle` for an on and off state.** It reports whether it's pressed; a `Toolbar.Button` only runs an action. Put toggles that pick one of a set, such as alignment, in a `Toolbar.ToggleGroup`.
- **Wrap popup triggers, not the button.** Pass `Toolbar.Button` to a `Menu.Trigger`, `Popover.Trigger`, or `Tooltip.Trigger` with `render`, so it keeps the toolbar's look and arrow order.
- **Label every icon-only control,** and the toolbar itself.

## Accessibility

- Renders `role='toolbar'` with `aria-orientation`. Give it an `aria-label`, or point `aria-labelledby` at a visible heading.
- **Keyboard:** `Tab` moves into the toolbar and out again in one stop. Arrow keys move between items (`ArrowLeft` and `ArrowRight`, or `ArrowUp` and `ArrowDown` when vertical). Focus wraps from the last item to the first unless `loopFocus` is `false`.
- A disabled `Toolbar.Button` keeps focus, with `aria-disabled`, so a screen reader still announces it.
- `Toolbar.Separator` renders `role='separator'`, running across the toolbar.
