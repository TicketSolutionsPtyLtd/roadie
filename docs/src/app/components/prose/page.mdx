Typesets rich HTML from a CMS, Markdown, or user content.

Prose renders the core [`.prose` class](/foundations/prose/), which styles the
bare headings, paragraphs, lists, tables, code, quotes, rules, figures, and keys
inside it. It sets the rhythm, a 65ch measure, and every colour from Roadie
tokens.

## Import

```tsx
import { Prose } from '@oztix/roadie-components/prose'
```

## Examples

### Default

```tsx-live-prose
<Prose>
  <h2>Ochre Kite Weekender 2026</h2>
  <p>
    Gates open at <strong>11am</strong> on Saturday. Bring a printed or{' '}
    <a href='#'>mobile ticket</a>, and show it at the north gate.
  </p>
  <h3>What to bring</h3>
  <ul>
    <li>Photo ID for the bar</li>
    <li>Sunscreen and a refillable bottle</li>
  </ul>
  <p>
    Set <code>data-ticket</code> on the scanner link to open the right wallet.
  </p>
</Prose>
```

### Sizes

`sm` sets 14px body text with the UI heading styles and a tighter rhythm, for
dense content such as an FAQ or a sidebar. `md` is the default. `lg` sets
larger body text for editorial pages. Both use the prose heading styles.

```tsx-live-prose
<div className='grid gap-8'>
  <Prose size='sm'>
    <h3>Can I change the name on my ticket?</h3>
    <p>Yes, up to 48 hours before doors. Open the ticket and choose Transfer.</p>
  </Prose>
  <Prose size='md'>
    <h3>Getting there</h3>
    <p>Catch the festival shuttle from the city, then walk the marked path.</p>
  </Prose>
  <Prose size='lg'>
    <h3>A weekend at Jumbuck Orchard Park</h3>
    <p>Three stages, two nights, and the longest bar in the valley.</p>
  </Prose>
</div>
```

Each size only sets `--prose-*` variables, so a class such as
`[--prose-flow:2em]` on Prose adjusts it further. The
[variables table](/foundations/prose/#variables) lists them all.

### Custom element

Use `render` to draw Prose as a semantic element. The deprecated `as` prop
still works the same way.

```tsx-live-prose
<Prose render={<article />}>
  <h2>Conditions of entry</h2>
  <p>
    This renders as an <code>&lt;article&gt;</code> element instead of a{' '}
    <code>&lt;div&gt;</code>.
  </p>
</Prose>
```

### Tables

Tables shrink to fit their content. Wrap one that might be wider than the
column in `.prose-scroll`, so it scrolls sideways instead of overflowing.

```tsx-live-prose
<Prose>
  <div className='prose-scroll'>
    <table>
      <thead>
        <tr>
          <th>Session</th>
          <th>Stage</th>
          <th>Doors</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <td>Feathered Anchor Sessions</td>
          <td>Main</td>
          <td>7:30pm</td>
        </tr>
        <tr>
          <td>Lampshade Disco</td>
          <td>Tent</td>
          <td>10:00pm</td>
        </tr>
      </tbody>
    </table>
  </div>
</Prose>
```

### Opting out

Add `.not-prose` or `data-not-prose` to an element inside Prose to keep the
styles away from it and everything inside it. The
[prose foundation](/foundations/prose/#opting-out) covers how an escaped child
keeps its place in the rhythm.

A button or link button that renders an `<a>` inside Prose gets the prose
underline. Wrap it in `.not-prose` to keep its own styles.

```tsx-live-prose
<Prose>
  <p>Tickets go on sale Friday at 9am.</p>
  <div className='not-prose flex flex-wrap gap-2'>
    <Button href='#' intent='accent' emphasis='strong'>
      Buy tickets
    </Button>
    <Button href='#'>Set a reminder</Button>
  </div>
</Prose>
```

## Guidelines

- Use Prose for rendered content, such as CMS output, Markdown, and user HTML.
  For app UI, use the display and text utilities directly.
- A Prose inside a `.not-prose` element stays unstyled, so put the escape
  around the parts that need it, not around a region that also holds Prose.
- Use `render` rather than `as` to set the element; `as` is removed in v3.
