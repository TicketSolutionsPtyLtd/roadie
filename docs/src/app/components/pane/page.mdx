A scrolling column of an application frame — sticky chrome, its own scroll, and
a stack position when the panes have to share a screen.

## Import

```tsx
import { Pane } from '@oztix/roadie-components/pane'
```

## Anatomy

A pane is a `<section>` that owns a surface, a shape and a scroll. Its body
scrolls beneath a sticky `Pane.Header` and above a sticky `Pane.Footer`; the
page itself never scrolls.

A pane works on its own — every example but Roles and Stacking is a
standalone pane in a fixed-height box. Put panes side by side inside
[`Navigator.Content`](/components/navigator) and they gain an arrangement: a
row of columns where there is room, a stack where there isn't.

A docs frame is its own container: the columns below respond to the frame's
width, not the window's. Narrow the window to see the stack; widen it to see
the columns arrive.

## Examples

### Default

A pane in a box. `Pane.Header` is sticky, the body scrolls under it, and the
scrollbar is the pane's own — nothing on the page moves.

```tsx-live
<div className='h-80 rounded-2xl bg-sunken p-3'>
  <Pane role='detail' className='h-full'>
    <Pane.Header>
      <Pane.Title>Midnight Frequency</Pane.Title>
    </Pane.Header>
    <List>
      <List.Item title='General admission' subtitle='$68.00 · on sale' chevron />
      <List.Item title='Early bird' subtitle='$54.00 · sold out' chevron />
      <List.Item title='VIP booth' subtitle='$180.00 · 6 remaining' chevron />
      <List.Item title='Group of 6' subtitle='$360.00 · on sale' chevron />
      <List.Item title='Accessible seating' subtitle='$68.00 · on sale' chevron />
      <List.Item title='Companion' subtitle='$0.00 · on request' chevron />
      <List.Item title='Doors' subtitle='7:00 pm' />
      <List.Item title='Support act' subtitle='The Paper Kites' />
    </List>
  </Pane>
</div>
```

The `List` above declares no padding. A pane publishes `--content-inset` and
pads its scrolling content by it, and its chrome — `Pane.Header`,
`Pane.Search`, `Pane.Footer` — reads the same variable back, so header title
and body text land on one edge. A `subtler` `List` then bleeds its rows back
out by their own row padding, so the interactive background sits wider than
the text without moving it.

### Roles

`role` is a default depth plus a yield order, not a taxonomy. `list` is the
root (depth 0), `detail` sits under it (depth 1), and `inspector` is a fixed
14rem track off the stack that yields first — it shows only once every level
of the stack fits beside it, at 44.25rem with one level, 69rem with two and
85.75rem with three. Column widths come from position, not role: the
right-most visible pane fills and every pane to its left takes a parent
track, at least 16rem.

Yielding is not disappearing. The **consumer** declares the small-screen
affordance, and the natural one is a [`Drawer`](/components/drawer) in the
detail pane's `Pane.Actions`. That hands dismissal, focus trapping, Escape and
the scrim to Base UI instead of a hand-rolled overlay, and
`pane-inspector-yielded:` shows the trigger exactly while the column is gone.

```tsx-live-noinline
function Roles() {
  const [open, setOpen] = useState(false)
  const [showDetail, setShowDetail] = useState(true)
  const tiers = [
    { title: 'General admission', subtitle: '$68.00 · on sale' },
    { title: 'Early bird', subtitle: '$54.00 · sold out' },
    { title: 'VIP booth', subtitle: '$180.00 · 6 remaining' },
    { title: 'Group of 6', subtitle: '$360.00 · on sale' },
    { title: 'Accessible seating', subtitle: '$68.00 · on sale' }
  ]
  return (
    <div className='h-[30rem] overflow-hidden rounded-2xl border border-subtle'>
      <Navigator className='h-full'>
        <Navigator.Content>
          <Pane role='list' aria-label='Events'>
            <Pane.Header>
              <Pane.Title>Events</Pane.Title>
            </Pane.Header>
            <List>
              <List.Item title='Midnight Frequency' subtitle='60 remaining' current onClick={() => setShowDetail(true)} />
              <List.Item title='Sunset Sounds' subtitle='180 remaining' />
              <List.Item title='Neon Dusk' subtitle='460 remaining' />
              <List.Item title='Harbour Lights' subtitle='sold out' />
            </List>
          </Pane>
          <Pane role='detail' aria-label='Midnight Frequency' current={showDetail}>
            <Pane.Header onBack={() => setShowDetail(false)}>
              <Pane.Title>Midnight Frequency</Pane.Title>
              <Pane.Actions>
                <Drawer open={open} onOpenChange={setOpen} side='bottom'>
                  <Drawer.Trigger
                    render={
                      <IconButton
                        aria-label='Event details'
                        emphasis='normal'
                        className='pane-inspector-yielded:inline-flex hidden'
                      >
                        <InfoIcon weight='bold' className='size-5' />
                      </IconButton>
                    }
                  />
                  <Drawer.Content aria-label='Event details'>
                    <Drawer.Body className='py-4'>
                      <List emphasis='subtler'>
                        <List.Item title='Venue' subtitle='The Tivoli' />
                        <List.Item title='Doors' subtitle='7:00 pm' />
                        <List.Item title='Capacity' subtitle='1,300' />
                      </List>
                    </Drawer.Body>
                  </Drawer.Content>
                </Drawer>
              </Pane.Actions>
            </Pane.Header>
            <List>
              {tiers.map((tier) => (
                <List.Item key={tier.title} title={tier.title} subtitle={tier.subtitle} chevron />
              ))}
            </List>
          </Pane>
          <Pane role='inspector' emphasis='subtler' aria-label='Event details'>
            <Pane.Header>
              <Pane.Title>Details</Pane.Title>
            </Pane.Header>
            <List emphasis='subtler'>
              <List.Item title='Venue' subtitle='The Tivoli' />
              <List.Item title='Doors' subtitle='7:00 pm' />
              <List.Item title='Capacity' subtitle='1,300' />
            </List>
          </Pane>
        </Navigator.Content>
      </Navigator>
    </div>
  )
}
render(<Roles />)
```

### Stacking

Panes are columns where there is room and a stack where there isn't, and
`Navigator.Content` decides from its own width: two columns from 46.25rem,
three from 63rem, one below that. The right-most column fills; the ones to
its left take a parent track.

Every pane has a `depth` — `list` defaults to 0, `detail` to 1, a sub-detail
declares `depth={2}` — and the deepest `current` pane is the top. The top is
always on screen; the panes behind it fill the remaining columns nearest
first, so the left-most pane drops first. In the stack only the top shows,
and push and pop between depths slide. In the columns nothing animates.

Select a row below, then resize the window — the same declaration is a
side-by-side reveal where two columns fit and a push where they don't.

```tsx-live-noinline
function Stacking() {
  const [selected, setSelected] = useState(null)
  const events = [
    { id: 'midnight', title: 'Midnight Frequency', subtitle: '1,240 sold · 60 remaining' },
    { id: 'sunset', title: 'Sunset Sounds', subtitle: '820 sold · 180 remaining' },
    { id: 'neon', title: 'Neon Dusk', subtitle: '540 sold · 460 remaining' },
    { id: 'harbour', title: 'Harbour Lights', subtitle: '2,010 sold · sold out' }
  ]
  const event = events.find((e) => e.id === selected)
  return (
    <div className='h-[30rem] overflow-hidden rounded-2xl border border-subtle'>
      <Navigator className='h-full'>
        <Navigator.Content>
          <Pane role='list' aria-label='Events'>
            <Pane.Header>
              <Pane.Title>Events</Pane.Title>
            </Pane.Header>
            <List>
              {events.map((e) => (
                <List.Item
                  key={e.id}
                  title={e.title}
                  subtitle={e.subtitle}
                  chevron
                  current={selected === e.id}
                  onClick={() => setSelected(e.id)}
                />
              ))}
            </List>
          </Pane>
          <Pane role='detail' current={event != null} aria-label='Event'>
            <Pane.Header onBack={() => setSelected(null)} backLabel='Events'>
              <Pane.Title>{event ? event.title : 'Nothing selected'}</Pane.Title>
            </Pane.Header>
            <div className='grid gap-3 pb-4'>
              <p className='text-subtle'>
                {event ? event.subtitle : 'Pick an event from the list.'}
              </p>
            </div>
          </Pane>
        </Navigator.Content>
      </Navigator>
    </div>
  )
}
render(<Stacking />)
```

### Composition

`Pane.Header` holds a top row — the back affordance on the left, `Pane.Actions`
on the right — with the title, a `Pane.Search` and anything else flowing
beneath it at full width. `Pane.Footer` is the same material at the foot of the
pane.

Actions use each control's default size. The top row is chrome a user acts on,
not a dense toolbar, so a `<Button>` or `<IconButton>` sits there unsized.

`Pane.Search` is a styled controlled input and nothing more. Filtering is a
plain `.filter()` over your own data before you render the rows. A searchable
`Navigator.Secondary` renders its own pill search with a Cancel button, not
`Pane.Search`.

```tsx-live-noinline
function Composed() {
  const [query, setQuery] = useState('')
  const rows = [
    'General admission',
    'Early bird',
    'VIP booth',
    'Group of 6',
    'Accessible seating',
    'Companion'
  ]
  const shown = rows.filter((row) =>
    row.toLowerCase().includes(query.toLowerCase())
  )
  return (
    <div className='h-96 rounded-2xl bg-sunken p-3'>
      <Pane role='detail' className='h-full'>
        <Pane.Header onBack={() => setQuery('')}>
          <Pane.Title>Ticket types</Pane.Title>
          <Pane.Actions>
            <Button intent='accent' emphasis='strong'>
              Publish
            </Button>
          </Pane.Actions>
          <Pane.Search
            value={query}
            onValueChange={setQuery}
            placeholder='Filter ticket types'
          />
        </Pane.Header>
        <List>
          {shown.map((row) => (
            <List.Item key={row} title={row} chevron />
          ))}
        </List>
        {shown.length === 0 ? (
          <p className='py-3 text-sm text-subtle'>No matches</p>
        ) : null}
        <Pane.Footer>
          <Button size='sm' emphasis='normal'>
            Add ticket type
          </Button>
        </Pane.Footer>
      </Pane>
    </div>
  )
}
render(<Composed />)
```

The back affordance appears on a non-root pane with a target. On its own, as
here, a pane is the left-most thing on screen, so it shows Back at every
width; inside `Navigator.Content` the columns decide, below.

### Back, Close, or nothing

One leading cell, at most one glyph, decided by where the pane sits in the
columns:

| The pane is… | It shows |
| --- | --- |
| the root (depth 0) | nothing, ever |
| the left-most visible pane, with a parent that dropped | **Back**, to that parent |
| the top pane, with its parent visible beside it | **Close** |
| a middle column | nothing |
| not yet reached (a placeholder detail) | nothing |

On a phone the only visible pane is the top, so it is also the left-most: it
gets Back. Both buttons go to the same place — one level up. Back
navigates because the parent is off screen; Close only ever draws where
going up removes that column, so `backHref` drives both:

```tsx
<Pane role='detail' depth={2} current>
  <Pane.Header backHref='/tickets/glamping' backLabel='Glamping'>
    <Pane.Title>Sam Okafor</Pane.Title>
  </Pane.Header>
</Pane>
```

Back is always the round caret button. `backLabel` is the parent's title, and
it names Back for assistive tech — "Back to Glamping" — without showing on
screen; without it the button reads "Back". Under a section's generated list
the depth-1 pane gets the section route and label from `Navigator` with
nothing declared.

`onBack` is the same target as a handler, and `onClose` overrides it for
Close alone:

```tsx
<Pane role='detail' current={event != null}>
  <Pane.Header onBack={() => setSelected(null)} onClose={() => setEvent(null)}>
    <Pane.Title>{event?.title}</Pane.Title>
  </Pane.Header>
</Pane>
```

Roadie can't close a pane it doesn't own — whether a column disappears is
your own routing or state, so the affordance only appears once you supply a
target. It never appears on the root pane, even if you thread the same handler
to every pane uniformly: the component knows which pane is the base of the
stack and withholds Close there itself.

### Collapse on scroll

`Pane.Header` takes a docked shadow and its title collapses as the pane
scrolls — automatically, with no prop. `Pane.Title` renders both the large
heading and a compact echo; the echo cross-fades in, centred between the back
affordance and `Pane.Actions`, and is the only one that responds to a tap —
tapping it scrolls the pane back to the top. Expanded, the tap would be a
no-op, so only the collapsed echo is reachable.

`Pane.Title` must be a **direct child** of `Pane.Header`, same as
`Pane.Actions` — the compact echo places itself in the header's grid, and grid
placement only reaches direct children.

The header's height change is animated too, not just the cross-fade — the
title's row transitions `grid-template-rows` (`1fr` → `0fr`) and its own top
margin alongside the `scale`/`opacity` fade, so the header shrinks
continuously instead of snapping. Those are layout properties, and animating
them is a deliberate, commented exception to this design system's
translate/scale/opacity-only rule: nothing else can reclaim the row's space,
and it costs one transition per collapse toggle rather than one per scroll
frame. The title itself never leaves the flow; its row closes underneath it.

### Body title

`Pane.BodyTitle` is the alternative: instead of living in `Pane.Header`, it
renders in the pane's own scrolling content, alongside whatever sits beside
it there. `Pane.Header` picks up its text through context and cross-fades in
the same compact echo a `Pane.Title` would have rendered itself — declare
`Pane.Header` with no title of its own.

```tsx-live
<div className='h-80 rounded-2xl bg-sunken p-3'>
  <Pane role='detail' className='h-full'>
    <Pane.Header />
    <div className='grid gap-3 pb-4'>
      <Pane.BodyTitle>Midnight Frequency</Pane.BodyTitle>
      <p className='text-subtle'>Sat 14 Feb · The Tivoli · 60 remaining</p>
    </div>
  </Pane>
</div>
```

**Recommended.** Nothing about the header's box depends on the title, so
there is nothing to animate at all — the header holds one constant height for
the whole cross-fade, where the in-header arrangement above still pays for a
`grid-template-rows` transition on every collapse toggle, the one layout
property this design system otherwise never animates.

`Pane.BodyTitle` defaults to `text-display-ui-3`. Pass a `text-display-*`
utility through `className` to size it differently — Tailwind's merge
replaces the default rather than joining it, so there is no separate size
prop to reach for.

`Pane.BodyTitle` applies no inset of its own. It is content, not chrome — what
it has to align with is its content neighbours, not the pane's edge — so it
takes the pane's content inset with the rest of the body, as in the example
above, and a container that republishes `--content-inset` carries it along.

Declaring both is a mistake, not a fallback: if a `Pane.Header` contains a
`Pane.Title` **and** the pane also has a `Pane.BodyTitle` in its content,
`Pane.Header` renders the `Pane.Title`'s echo and ignores the other, warning
to the console in development.

## Guidelines

<Guideline title='Declaration order is stack depth'>
  <Guideline.Do code={`<Navigator.Content>\n  <Pane role='list' />\n  <Pane role='detail' current={selected != null} />\n</Navigator.Content>`}>
    Author panes shallowest first. Document order is depth once panes have
    mounted; `depth` (defaulting from `role`) is what the server render
    uses, so declare `depth={2}` on a sub-detail.
  </Guideline.Do>
  <Guideline.Dont code={`<Navigator.Content>\n  <Pane role='detail' current />\n  <Pane role='list' />\n</Navigator.Content>`}>
    A pane authored out of depth order parks on the wrong side, so the push
    slides in from the left and the pop from the right. This is a **visual**
    assumption, not just a bookkeeping one.
  </Guideline.Dont>
</Guideline>

<Guideline title='Panes can sit anywhere in the subtree'>
  <Guideline.Do code={`<Navigator.Content>\n  <EventSlot>\n    <Pane role='list' />\n  </EventSlot>\n  <DetailSlot>\n    <Pane role='detail' current />\n  </DetailSlot>\n</Navigator.Content>`}>
    A pane announces itself to the nearest `Navigator.Content` through
    context, wherever it sits in that subtree. A pane returned by a route, a
    Next.js parallel-route slot, or a plain wrapper component all participate
    in the stack normally — there is no direct-child requirement.
  </Guideline.Do>
  <Guideline.Dont code={`<Navigator.Content>\n  {/* renders children but no <Pane> anywhere */}\n  <div>Not a pane</div>\n</Navigator.Content>`}>
    What still breaks is having **no `Pane` at all** reachable in the
    subtree — nothing registers, so stack position, push/pop motion, the
    section's list pane and `primaryNav` all stay inert. In development,
    `Navigator.Content` warns to the console when this happens.
  </Guideline.Dont>
</Guideline>

<Guideline title='Pane.Actions belongs directly under Pane.Header'>
  <Guideline.Do code={`<Pane.Header backHref='/events'>\n  <Pane.Title>Midnight Frequency</Pane.Title>\n  <Pane.Actions>\n    <Button>Publish</Button>\n  </Pane.Actions>\n</Pane.Header>`}>
    Actions place themselves in the header's grid, opposite the back
    affordance. Grid placement only reaches direct children.
  </Guideline.Do>
  <Guideline.Dont code={`<Pane.Header backHref='/events'>\n  <div className='flex justify-between'>\n    <Pane.Title>Midnight Frequency</Pane.Title>\n    <Pane.Actions>…</Pane.Actions>\n  </div>\n</Pane.Header>`}>
    Nested in a wrapper, the actions lose their cell and render below the top
    row instead of opposite the back affordance.
  </Guideline.Dont>
</Guideline>

<Guideline title='Give the root route a placeholder detail'>
  <Guideline.Do code={`<Navigator.Content>\n  <Pane role='list' />\n  <Pane role='detail' current={event != null}>\n    {event ? <EventDetail /> : <EmptyState title='No event selected' />}\n  </Pane>\n</Navigator.Content>`}>
    Render the detail pane on the root route too, as Mail's "No message
    selected". Unreached panes fill the leftover columns, so the row reads as
    a list beside an empty detail.
  </Guideline.Do>
  <Guideline.Dont code={`<Navigator.Content>\n  <Pane role='list' />\n  {event ? <Pane role='detail' current /> : null}\n</Navigator.Content>`}>
    Mount the detail only once something is selected. With one pane in the
    stack the list fills the whole row alone, then jumps to a parent track
    when the detail appears.
  </Guideline.Dont>
</Guideline>

- **`role` is a default depth plus yield order.** `list` is the root,
  `detail` sits under it, and an `inspector` is off the stack and yields
  first. Width comes from position: the right-most visible pane fills.
- **An `inspector` needs an affordance you declare.** It is a column only once
  every stack level fits beside it. Put a [`Drawer`](/components/drawer) in
  the detail pane's `Pane.Actions` and show its trigger with
  `pane-inspector-yielded:`.
- **`current` decides the top at every width.** The deepest `current` pane
  is always on screen; which of the panes behind it still fit is the
  container's call.
- **Filtering is your own `.filter()`.** `Pane.Search` carries no filter
  machinery on purpose. The predicate registry it replaces existed only so
  filtered-out rows could stay declared and keep navigation state alive — a
  constraint that no longer exists.
- **A pane scrolls natively, and `List` does not virtualise.** That is fine
  into the hundreds of rows. A list in the thousands wants virtualisation,
  which `Pane` neither provides nor prevents — the scroll container is the
  viewport at `[data-slot="pane-viewport"]`.
- **`--content-inset` is the pane's one alignment number.** The pane pads its
  scrolling content by it and its chrome reads it back, so a `List` dropped
  straight in aligns with the header title without declaring padding. It is
  the same contract `Drawer` and `Accordion` publish, so a component
  written against it works in any of them.

## Accessibility

- The pane renders a `<section>`. Pass `aria-label` to make it a **named
  region** — without one it is an unlabelled section and carries no landmark
  weight.
- `Pane.Title` is an `<h2>`, so a pane heading never collides with the page's
  own `<h1>`. `Pane.BodyTitle` defaults to `<h1>` instead — it is the page's
  own heading, not a heading nested under one, so declare at most one per
  pane and none of your own alongside it.
- The back affordance is a labelled `IconButton` — "Back", or "Back to
  Events" with `backLabel='Events'`. It appears on the left-most visible non-root
  pane: the top pane on a phone, or a parent column whose own parent has
  dropped.
- The close affordance is a labelled `IconButton` ("Close"), from `onClose`,
  `onBack` or `backHref` in that order. It appears only on the top pane while
  its parent is visible beside it, and never on the root pane.
- `Pane.Search` is a `type='search'` input named by its `placeholder`, so it
  reads as a searchbox with an accessible name.
- A pane that doesn't fit — covered in the stack, or dropped from the
  columns — is hidden, so neither taps nor assistive technology reach it.
