Roadie has one table for working through records and one for reading a
summary. Pick by what people do with the rows, then shape the columns so the
same record reads the same way in a pane, in a dashboard, and on paper.

## Choose by job

| Component                               | Use it for                                                                                               | Where it lives                                     | Rows              |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ----------------- |
| [RecordTable](/components/record-table) | A working list people search, sort, select, and page through. Turns into list rows or cards when narrow. | A Pane, most of the time                           | Any number        |
| [DataTable](/charts/data-table)         | A read-only summary. Renders on the server, so it also prints in reports, PDFs, and slides.              | A DataCard on a dashboard, a detail page, or a PDF | About 25 or fewer |
| [List](/components/list)                | A few records to open, or settings. No columns to compare.                                               | A detail page, a menu pane, or settings            | About 10 or fewer |
| [Card grid](/components/card)           | Browsing where an image leads, like event tiles. No sorting.                                             | A home or discovery page                           | A screen or two   |
| [StatTile](/charts/stat-tile)           | One number that matters, with its change.                                                                | A dashboard row or the top of a detail page        | One value         |

### Signs you picked the wrong one

- A DataTable gains a search box or a pager. It has become a working list. Use
  a RecordTable.
- A RecordTable holds five rows nobody searches. Use a DataTable, or a List
  when each row opens something.
- A card grid gets sort controls. People are comparing, not browsing. Use a
  RecordTable.
- A dashboard card lists people or orders. Show the count in a StatTile and
  link to the pane that lists them.
- A table has one row. Show the values as a StatTile or a description list.

## Records live in a Pane

Most RecordTables fill a [Pane](/components/pane): the title in the header,
the toolbar with its search above the rows in the body, and the pager in the
footer. Keep the search in the table's toolbar, not in `Pane.Search`. The
RecordTable page has a [complete pane](/components/record-table#in-a-pane) to
copy.

## Columns

- Describe the record once. Build its fields with `recordFields`, then build
  columns from them with `tableColumns`. A field's type decides how its values
  read, everywhere it shows. See [Records model](/foundations/records).
- One title column. Pin it with `pin: true`. A column with
  `narrow: 'title'`, or else the first pinned text column, or else the first
  text column, reads as the row's title, in strong text.
- Numbers end-aligned. Number and money fields do this, and sort largest
  first.
- Money. `currency` where cents matter, an order total or a payout.
  `compactCurrency` for gross across events, where $118k reads faster than
  $118,400. A field with `currencyKey` names any currency that isn't dollars.
- Dates. Event and access dates read in the venue's zone through
  `timeZoneKey`, long with the weekday. Timestamps read in the reader's zone,
  medium with the time. See [Date and time](/foundations/date-and-time).
- Status as a Badge. Give an option field a `status` map of each key to its
  intent, chosen by meaning. It shows a small Badge in normal emphasis and
  sorts by each key's `order`.
- Ids in monospace. Order numbers, references, and promo codes, through
  `font-mono` in the column's `cell`.
- Give each column its place on a phone. Under 40rem the table lists its
  records. The title column takes `narrow: 'title'`, one line under it
  `'description'`, and a status `'trailing'`. Any `'detail'` column turns rows
  into cards; keep it to three or four details. The rest stay in the wide
  table.
- Let the extras go first. Give columns people can do without a `priority` so
  they hide as the table narrows, 3 first, before it turns into list rows.
- Images lead. An image column, with `kind: 'image'`, shows a thumbnail, leads
  a list row, and becomes a card's banner.
- Hide the rest. A view's `layout.columns.hidden` hides columns, and its
  `order` reorders them. Pinned columns stay first and shown.

## Table examples

### Orders

A working list in its own box, newest first. The order number is the pinned
title, in monospace through its cell, and the status reads as a Badge. Under
40rem each row shows the customer under the order number and the status on
the end.

```tsx-live-noinline-expand
const customers = ['Mia Tran', 'Jack Ellis', 'Ava Nguyen', 'Noah Smith', 'Isla Brown', 'Leo Wilson']
const eventNames = ['Ochre Kite Weekender', 'Marzipan Thunderclap', 'Corduroy Lagoon Sessions', 'Velvet Dingo Fest']
const statuses = ['paid', 'paid', 'paid', 'pending', 'refunded']
const orders = Array.from({ length: 60 }, (_, index) => ({
  id: `order-${index}`,
  number: `OZ-${48210 + index * 7}`,
  customer: customers[index % customers.length],
  event: eventNames[index % eventNames.length],
  status: statuses[index % statuses.length],
  placedAt: new Date(Date.UTC(2026, 9, 1, 0, 15) + index * 5 * 3600000).toISOString(),
  total: [79.9, 149, 59, 238.5][index % 4]
}))

const field = recordFields()
const fields = [
  field.text('number', { label: 'Order' }),
  field.text('customer', { label: 'Customer' }),
  field.text('event', { label: 'Event' }),
  field.option('status', {
    label: 'Status',
    status: { paid: { intent: 'success' }, pending: { intent: 'warning' }, refunded: { intent: 'neutral' } }
  }),
  field.date('placedAt', { label: 'Placed', moment: 'timestamp' }),
  field.money('total', { label: 'Total', format: 'currency' })
]

const column = tableColumns(fields)
const columns = [
  column.field('number', {
    pin: true,
    width: { min: 7 },
    cell: ({ row }) => <span className='font-mono font-semibold text-strong'>{row.number}</span>
  }),
  column.field('customer', { narrow: 'description' }),
  column.field('event'),
  column.field('status', { narrow: 'trailing' }),
  column.field('placedAt'),
  column.field('total')
]

render(
  <RecordTable
    caption='Orders'
    data={orders}
    fields={fields}
    columns={columns}
    getRowId={(row) => row.id}
    recordName={{ one: 'order', other: 'orders' }}
    defaultView={{ query: { sort: [{ field: 'placedAt', direction: 'descending' }] } }}
    maxHeight='28rem'
  />
)
```

### Top events in a dashboard

A DataTable in a DataCard. Five rows, sorted by gross, with the venue as
secondary text and sell-through as a meter.

```tsx-live
<div className='w-full max-w-md'>
  <DataCard
    label='Top events'
    takeaway='Ochre Kite Weekender leads gross this month'
    source='Oztix sales. Gross before fees.'
  >
    <DataTable
      caption='Top events by gross'
      columns={[
        { key: 'event', header: 'Event', kind: 'text', pin: true, secondaryKey: 'venue' },
        { key: 'sellThrough', header: 'Sell-through', kind: 'meter', target: 0.85 },
        { key: 'gross', header: 'Gross', kind: 'number', format: 'compactCurrency' }
      ]}
      rows={[
        { event: 'Ochre Kite Weekender', venue: 'Kazoo Hollow Room, Brisbane', sellThrough: 0.94, gross: 212400 },
        { event: 'Marzipan Thunderclap', venue: 'The Quilted Walrus Room, Melbourne', sellThrough: 0.81, gross: 168900 },
        { event: 'Corduroy Lagoon Sessions', venue: 'Drongo Bell Social Club, Adelaide', sellThrough: 0.66, gross: 97300 },

        { event: 'Sapphire Cassowary Night', venue: 'Kazoo Hollow Room, Brisbane', sellThrough: 0.37, gross: 28800 }

```

## Oztix records by context

Each record lists its RecordTable columns with the type of the field behind
each one, how it reads, where it goes on a phone (`narrow`), and which hide
first as the table narrows (`priority`), then how the record appears
everywhere else.

### Event

A show or session at a venue. The record most panes start from.

| Column         | Field type | Shows as                                                         | Narrow      | Priority |
| -------------- | ---------- | ---------------------------------------------------------------- | ----------- | -------- |
| Event (pinned) | text       | Strong text                                                      | title       |          |
| Venue          | option     | Option label                                                     | description |          |
| Status         | option     | Badge                                                            | trailing    |          |
| Starts         | date       | Long date and time in the venue's zone (Fri 27 Nov 2026, 7:30pm) | detail      |          |
| Sold           | number     | Number                                                           | detail      |          |
| Capacity       | number     | Number                                                           |             | 2        |
| Gross          | money      | Compact currency                                                 | detail      |          |

| Context       | How it shows                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| In a Pane     | Search by event or venue. Sort by start date, soonest first. See the [Events pane](/components/record-table#in-a-pane) example.       |
| On a phone    | Cards: the event, the venue under it, and the status on the end, with starts, sold, and gross as details.                             |
| Dashboard     | Top events: Event with the venue as secondary text, a sell-through meter, and Gross. Sort by gross, largest first. Five rows.         |
| Detail page   | The event page leads with image, date, and venue, then stat tiles for sold, gross, and sell-through. Ticket types sit in a DataTable. |
| PDF or report | An event report: the ticket type DataTable, plain, and charts drawn with `renderChartSvg`.                                            |
