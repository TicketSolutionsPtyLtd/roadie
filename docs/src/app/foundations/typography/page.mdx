Use pre-composed text styles. Let fluid type handle responsiveness. Pair
semantic colours with semantic HTML.

Roadie has two font families: Intermission, a sans-serif set with
`font-sans`, and IBM Plex Mono, a monospace set with `font-mono`.

## Type scale

Sizes from `text-lg` up use `clamp()` to scale fluidly between viewport
widths, so they need no breakpoint overrides. On the docs site, each step is
set in its own size, with its size in pixels or its fluid range.

## Text style utilities

Pre-composed utilities combine font size, weight, line height, and letter
spacing. They come in two contexts: UI for app interfaces, and prose for
long-form content.

### Display styles

UI display styles are compact headings for dashboards, settings, and
navigation, with tighter line height and tracking. Prose display styles are
larger, heavier headings for articles, marketing pages, and rich content,
designed for reading. On the docs site, each style is set in its own style,
UI first, then prose.

### Body text styles

`body` already sets `text-ui`, so standard UI text needs no class. Each style
takes the line height and letter spacing of its context.

```tsx-live layout=stack
{/* text-ui */}
<p className='text-ui'>App interface text with a tighter line height.</p>
{/* text-prose */}
<p className='text-prose'>
  Long-form content with a more generous line height, better for extended
  reading such as articles and documentation.
</p>
{/* text-ui-meta */}
<p className='text-ui-meta'>Secondary UI text, such as timestamps, counts, and helper text.</p>
{/* text-code */}
<p className='text-code'>const roadie = 'monospaced code text'</p>
```

| Utility        | Use for                                                  | Size   | Context |
| -------------- | -------------------------------------------------------- | ------ | ------- |
| `text-ui`      | App interface text, and the default on `body`            | `base` | `ui`    |
| `text-prose`   | Long-form content, such as articles and documentation    | `base` | `prose` |
| `text-ui-meta` | Secondary UI text, such as timestamps, counts, and hints | `sm`   | `ui`    |
| `text-code`    | Monospaced code                                          | `sm`   | `code`  |

## Line height and tracking

Semantic tokens keep rhythm consistent. Text style utilities set them by
themselves, so use the tokens on their own only for custom compositions. On
the docs site, each context is listed with its line height and letter
spacing.

## Semantic text colours

Use semantic colour utilities instead of raw colour values. They adapt to
intents, themes, and dark mode by themselves.

```tsx-live layout=stack gap=1
<p className='text-strong'>text-strong for headings, emphasis, and high contrast</p>
<p className='text-normal'>text-normal for body text, inherited from the body reset</p>
<p className='text-subtle'>text-subtle for secondary text and descriptions</p>
<p className='text-subtler'>text-subtler for meta text, timestamps, and hints</p>
```

## Usage

### Headings

Use raw heading elements with a display style utility and `text-strong`.
Match the semantic level, `h1` to `h6`, to the document structure, and the
visual style to the context.

```tsx-live layout=stack gap=2
<h1 className='text-display-ui-1 text-strong'>Page title</h1>
<h2 className='text-display-ui-3 text-strong'>Section</h2>
<h3 className='text-display-ui-5 text-strong'>Subsection</h3>
```

### Body text

Body inherits `text-ui` from the reset. Use `<p>` elements with semantic
colour classes.

```tsx-live layout=stack gap=2
<p>Default body text. No class needed.</p>
<p className='text-subtle'>Secondary text</p>
<p className='text-sm text-subtler'>Meta or hint text</p>
<p className='text-strong'>Emphasised text</p>
```

### Prose content

Wrap CMS output, markdown, or user-generated content in `<Prose>` for
automatic typography and spacing. See [Prose styles](/foundations/prose).

```tsx-live-prose
<Prose>
  <h2>Article heading</h2>
  <p>
    Body paragraph with <strong>bold</strong> and <a href='#'>links</a>.
    The Prose component handles spacing, list styles, and element
    typography.
  </p>
  <ul>
    <li>List item one</li>
    <li>List item two</li>
  </ul>
</Prose>
```

## Numerals

Intermission has two sets of figures. Proportional is the default, and each
digit takes the width its shape wants. Tabular gives every digit the same
width, so values line up in a column.

<Guidelines>

<Guideline title='Tabular figures where numbers stack, proportional where they do not' description='Equal-width digits are for columns and ticks. On a large standalone figure they read as gappy, because the 1s carry the same width as the 0s with nothing to line up against.'>
  <Guideline.Do
    code={`
      table column   tabular-nums
      axis ticks     tabular-nums
      ticking clock  tabular-nums
      hero figure    proportional
    `}
  >
    Tabular where values sit above one another, or where a digit changes
    under the eye. Proportional everywhere else.
  </Guideline.Do>
  <Guideline.Dont code='hero figure    tabular-nums'>
    A large static number with gaps where the narrow digits are.
  </Guideline.Dont>
</Guideline>

</Guidelines>

A ticking countdown is the exception that proves the rule. Its digits don't
align with anything, but they change while somebody is watching, so tabular
figures stop the row shifting on every tick.

## Semantic elements

| Element          | When to use                       | Example                         |
| ---------------- | --------------------------------- | ------------------------------- |
| `<h1>` to `<h6>` | Section headings                  | `text-display-ui-3 text-strong` |
| `<p>`            | Body text and descriptions        | `text-subtle`                   |
| `<span>`         | Inline text fragments             | `text-sm text-subtler`          |
| `<strong>`       | Important text                    | `text-strong`                   |
| `<em>`           | Emphasis or stress                | Italic by default               |
| `<Code>`         | Inline code, tokens, and commands | `<Code>bg-normal</Code>`        |
| `<Prose>`        | CMS or markdown content           | `<Prose size='md'>...</Prose>`  |
