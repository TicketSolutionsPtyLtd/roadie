`@oztix/roadie-lint-plugin` checks the Roadie conventions a rule can be sure of: Phosphor icon imports, sizes, and weights, colour classes, arbitrary radius and z-index values, a `Card` without `Card.Content`, and jsdom tests that check what only a browser can. Calls that need judgement, such as which emphasis a surface takes, stay with review. It runs in ESLint and in oxlint, with the same rule IDs in both.

## Install

```bash
pnpm add -D @oztix/roadie-lint-plugin
```

It works with ESLint 9 and 10 on flat config (`eslint.config.js`), and with oxlint 1.88 or later. Both are optional peer dependencies, so install the one your app lints with.

Before 0.2.0, the package was `@oztix/roadie-eslint-plugin`. To move, change the name in `package.json` and in your config's import. The rules and their IDs are the same.

## Turn on the rules in ESLint

Add the recommended config to your config array.

```js
import roadie from '@oztix/roadie-lint-plugin'

export default [
  // Your other configs
  roadie.configs.recommended
]
```

It turns every rule in the [Rules](#rules) table on as an error for JavaScript and TypeScript files, and turns on JSX parsing. TypeScript files still need the parser your config gives them, such as typescript-eslint's.

To choose rules yourself, register the plugin as `roadie` and name each rule.

```js
import roadie from '@oztix/roadie-lint-plugin'

export default [
  {
    files: ['src/**/*.{ts,tsx}'],
    plugins: { roadie },
    rules: {
      'roadie/no-dark-variant': 'error',
      'roadie/phosphor-icon-weight': 'warn'
    }
  }
]
```

## Turn on the rules in oxlint

In `.oxlintrc.json`, extend the recommended preset by its path. Oxlint's `extends` takes a file path, not a package name.

```json
{
  "extends": [
    "./node_modules/@oztix/roadie-lint-plugin/oxlint/recommended.json"
  ]
}
```

In `oxlint.config.ts`, import the preset and extend it.

```ts
import { defineConfig } from 'oxlint'

import recommended from '@oztix/roadie-lint-plugin/oxlint/recommended.json' with {
  type: 'json'
}

export default defineConfig({ extends: [recommended] })
```

The preset turns every rule in the [Rules](#rules) table on as an error and loads the plugin under the name `roadie`. To choose rules yourself, load it in `jsPlugins` with that name and name each rule.

```json
{
  "jsPlugins": [
    { "name": "roadie", "specifier": "@oztix/roadie-lint-plugin" }
  ],
  "rules": {
    "roadie/no-dark-variant": "error",
    "roadie/phosphor-icon-weight": "warn"
  }
}
```

Without `name`, oxlint names the plugin after its package, so every rule ID would start with `@oztix/roadie-lint-plugin/` instead of `roadie/`.

## Rules

In a config, each rule takes the `roadie/` prefix, such as `roadie/no-dark-variant`.

| Rule                      | Fails                                                                    | Fix                                                           |
| ------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------- |
| `phosphor-icon-suffix`    | A Phosphor import by its bare name, such as `Heart`                      | Import `HeartIcon`                                            |
| `phosphor-icon-size-prop` | The `size` prop on a Phosphor icon                                       | A `size-*` class                                              |
| `phosphor-icon-weight`    | A Phosphor icon with no weight, or one other than bold, fill, or duotone | `weight='bold'`                                               |
| `no-dark-variant`         | A `dark:` variant                                                        | A semantic colour utility                                     |
| `no-hex-colour-class`     | A hex colour, such as `bg-[#fff]`                                        | A semantic colour utility                                     |
| `no-arbitrary-z-index`    | An arbitrary z-index, such as `z-[5]`                                    | A named z tier, or `z-1` inside a component                   |
| `no-arbitrary-radius`     | An arbitrary radius, such as `rounded-[10px]`                            | A named radius tier, such as `rounded-xl`                     |
| `card-content`            | A `Card` with no `Card.Content` among its parts                          | Put the body, or the title and description, in `Card.Content` |

[Iconography](/foundations/iconography) says which weight goes where, [Colors](/foundations/colors) why `.dark` needs no variant, [Elevation](/foundations/elevation) lists the z tiers, and [Shape](/foundations/shape) the radius tiers.

The class rules read `className`, any prop ending in `ClassName`, and the arguments of `cn`, `clsx`, `cva`, `cx`, `tv`, and `twMerge`. They also read a `const` those name, such as `variants` in `cn(variants[size])`, when it holds a string, array, or object. They follow one constant, not a constant built from another, and don't read CSS, so `@apply` goes unchecked. `roadie/no-arbitrary-radius` also fails a raw length, such as `[--card-radius:10px]`, in a variable that a `rounded-(--card-radius)` class reads.

Two icon rules skip a case on purpose. `roadie/phosphor-icon-weight` skips an icon passed to `Navigator.Item`, including one in a fallback such as `icon={icons[href] ?? <HouseIcon />}`, because Navigator sets its own weight. An icon built elsewhere, such as in a map of icons, still fails, so disable the rule around it and say why. `roadie/phosphor-icon-size-prop` allows `size='100%'`, which fills an SVG around the icon, such as a QR code's centre mark.

`roadie/card-content` judges a `Card` imported by name from `@oztix/roadie-components`, not through a namespace import, and only when it can see every part. A card whose children include your own component, an expression such as a `map`, or a fragment passes, since any of those might render `Card.Content`. Card warns in development when it renders without one, which catches the rest.

## Testing

The testing preset catches jsdom tests that check layout or CSS. jsdom has no layout engine and doesn't evaluate CSS, so those tests pass whatever the page looks like. The preset turns its rules on for `*.test.{js,jsx,ts,tsx}` files and off for `*.browser.test.*` files, such as tests in Vitest's browser mode, which is where those checks belong.

In ESLint, spread it into your config array.

```js
import roadie from '@oztix/roadie-lint-plugin'

export default [roadie.configs.recommended, ...roadie.configs.testing]
```

In oxlint, extend it after the recommended preset. In `oxlint.config.ts`, import `@oztix/roadie-lint-plugin/oxlint/testing.json` and add it to `extends` the same way.

```json
{
  "extends": [
    "./node_modules/@oztix/roadie-lint-plugin/oxlint/recommended.json",
    "./node_modules/@oztix/roadie-lint-plugin/oxlint/testing.json"
  ]
}
```

| Rule                      | Fails                                                                                                                       | Fix                                                                |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `no-css-class-in-jsdom`   | A `calc()`, container query, or breakpoint class in `toHaveClass`, such as `md:grid`                                        | Measure it in a browser test                                       |
| `no-css-source-in-jsdom`  | Reading CSS source, with a `?raw` import or `readFileSync`                                                                  | Set up the condition in a browser test and read the computed style |
| `no-layout-fake-in-jsdom` | A faked layout read, such as `getBoundingClientRect` or `offsetWidth`, or a `matchMedia` fake that answers a viewport query | A browser test at a real width                                     |

A `matchMedia` fake that answers only a preference, such as `prefers-reduced-motion`, passes, because it fakes a setting, not layout. A test that checks a generated file against the CSS it comes from is a fair reason to read CSS source. Turn `roadie/no-css-source-in-jsdom` off for that file in a config after the preset, and say why in a comment.

## Icons without an import

The Phosphor rules find icons by their import. Code that gets icons another way, such as a live code editor with icons in scope, names them in `settings.roadie.phosphorIcons`.

```js
import roadie from '@oztix/roadie-lint-plugin'

export default [
  roadie.configs.recommended,
  {
    settings: { roadie: { phosphorIcons: ['HeartIcon', 'StarIcon'] } }
  }
]
```

In oxlint, `settings` goes at the top level of the config. Oxlint fails to load a config with `settings` inside `overrides`.

```json
{
  "settings": {
    "roadie": { "phosphorIcons": ["HeartIcon", "StarIcon"] }
  }
}
```
