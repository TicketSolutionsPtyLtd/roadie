Horizontal bars, largest first by default, for channels, places and brackets.

## Import

```tsx
import { RankedBars } from '@oztix/roadie-charts/ranked-bars'
```

## Examples

### Default

```tsx-live width=140
<Chart label='Where buyers came from' source='Oztix sales.' size='md'>
  <RankedBars
    data={[
      { channel: 'Email', orders: 612 },
      { channel: 'Instagram', orders: 388 },
      { channel: 'Direct', orders: 301 },
      { channel: 'Venue site', orders: 164 }
    ]}
    x='channel'
    y='orders'
  />
</Chart>
```

### Highlight and Other

Past `limit` bars, the rest roll into Other, which always sits last. Ranked largest first, the rest are the smallest. When the label already says how many are left out, such as "Top 5 of 40 suburbs", set `other={false}` to leave Other off, so a long tail doesn't dwarf the top bar. With Other off, a highlighted bar past `limit` still shows, in place of the last bar that isn't highlighted, so the count stays at `limit` and the order holds. Shares stay of the full total.

```tsx-live width=140
<Chart label='Where buyers came from' source='Oztix sales.' size='md'>
  <RankedBars
    data={[['Email', 612], ['Instagram', 388], ['Direct', 301], ['Venue site', 164], ['TikTok', 142], ['Google', 97], ['Partner', 33]].map(([channel, orders]) => ({ channel, orders }))}
    x='channel'
    y='orders'
    highlight='Email'
    limit={5}
    takeaway='Email brings in over a third of orders'
  />
</Chart>
```

### Ordered categories

`sort={false}` keeps the data's order, for categories with an order of their own, such as age bands. Arrows then move through the bars in that order, and the bars past `limit` are the last in the data.

```tsx-live width=140
<Chart label='Buyers by age' source='Oztix sales.' size='md'>
  <RankedBars
    data={[['18 to 24', 412], ['25 to 34', 958], ['35 to 44', 503], ['45 to 54', 188], ['55 and over', 74]].map(([band, buyers]) => ({ band, buyers }))}
    x='band'
    y='buyers'
    sort={false}
    takeaway='Most buyers are 25 to 34'
  />
</Chart>
```

### Share

```tsx-live width=140
<Chart label='Where buyers live' source='Oztix sales, billing postcodes.' size='md'>
  <RankedBars
    data={[['Fortitude Valley', 205], ['West End', 161], ['Paddington', 132], ['Newstead', 102]].map(([suburb, buyers]) => ({ suburb, buyers }))}
    x='suburb'
    y='buyers'
    share
  />
</Chart>
```

### Reference

```tsx-live width=140
<Chart label='Turn-up' source='Oztix scans.' size='md'>
  <RankedBars
    data={[{ show: 'Friday', attended: 0.94, similar: 0.9 }, { show: 'Saturday', attended: 0.91, similar: 0.92 }, { show: 'Sunday matinee', attended: 0.83, similar: 0.86 }]}
    x='show'
    y='attended'
    format='percent'
    reference={{ field: 'similar', label: 'Similar shows' }}
  />
</Chart>
```

### Money

With `format='currency'`, every label, tooltip, and table cell shows cents, so the amounts line up. Set `trailingZeroDisplay='stripIfInteger'` to drop the cents from whole amounts, or `decimals` for another number of places.

```tsx-live width=140
<Chart label='Sales by payment method' source='Oztix sales.' size='md'>
  <RankedBars
    data={[
      { method: 'Card', value: 3116 },
      { method: 'Gift card', value: 634 },
      { method: 'Cash at the door', value: 556 },
      { method: 'Bank transfer', value: 365.5 }
    ]}
    x='method'
    y='value'
    format='currency'
  />
</Chart>
```

### Long names

Names share the plot with the bars. The label column takes up to 40% of the chart's width, so a long name wraps to two lines and then ends in an ellipsis.

```tsx-live width=140
<Chart label='Behind or at risk' context='Tickets a day to catch up' source='Oztix sales.' size='md'>
  <RankedBars
    data={[
      { show: 'Kelpie Moon Festival of Bonfires and Strange Machines, 31 Oct', perDay: 42 },
      { show: 'Uncle Meteor and the Midnight Spoon Orchestra Live, 2 Nov', perDay: 31 },
      { show: 'Giggling Lantern Comedy Gala for Very Serious People, 7 Nov', perDay: 18 },
      { show: 'Ember Galah Ball, 8 Nov', perDay: 9 }
    ]}
    x='show'
    y='perDay'
  />
</Chart>
```

## Guidelines

- Use ranked bars for shares of more than five parts, or parts close in size. Bars compare more accurately than arcs, so keep a [DonutChart](/charts/donut-chart) for one whole in two to five parts.
- Report shares, not counts, when totals differ between the things you compare.
- The table lists every row, including the ones rolled into Other or left off with `other={false}`.
- Keep names short enough to read at a glance. A cut name keeps its full text in the table, and shows it on hover.

## Accessibility

- The plot is one tab stop that starts on the top bar. Up and down arrows move between bars in the order they are drawn, and Home and End jump to the first and last.
- Each bar is read out with its value and, with `share`, its share of the total.
- The reference tick is keyed in the legend and read out with each bar.
