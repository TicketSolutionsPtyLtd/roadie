A dashboard’s period and what it compares with, in one picker.

## Import

```tsx
import { DashboardPeriod } from '@oztix/roadie-components/dashboard-period'
```

## Examples

### Default

One button shows the period and, when there is one, the dates it compares with: “This month 1 to 31 Oct 2026 vs 1 to 30 Sept 2026”. It opens a [DateRangePicker](/components/date-range-picker) that waits for Apply, because each change refetches every card. Its presets look ahead 30 and 90 days, back 30 days and 12 months, and over this financial year. Under the range, the Compare switch turns the comparison on, and Previous period or Previous year picks it, with the dates it covers below. Apply sends the period and its comparison together. The value is `{ range, compare }`, and no comparison leaves `compare` out.

```tsx-live-noinline
function Default() {
  const [period, setPeriod] = useState({ range: 'this-month', compare: 'previous-period' })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod value={period} onValueChange={setPeriod} />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Default />)
```

### With custom dates

A comparison can be custom dates, `{ start, end }`, set by the app. The button shows them, and the picker lists Custom dates beside Previous period and Previous year, so switching away and back keeps them. The picker doesn’t edit them.

```tsx-live-noinline
function Custom() {
  const [period, setPeriod] = useState({
    range: { start: '2026-11-02', end: '2026-11-08' },
    compare: { start: '2025-11-03', end: '2025-11-09' }
  })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod value={period} onValueChange={setPeriod} />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Custom />)
```

### With presets

`presets` replaces the period’s list, as on DateRangePicker. A sales dashboard reports on periods to date, so it takes the picker’s own `dateRangePresets`.

```tsx-live
<DashboardPeriod
  defaultValue={{ range: { period: 'month', offset: 0, toDate: true }, compare: 'previous-period' }}
  presets={dateRangePresets}
/>
```

### With the data’s dates

Pass the same `dataStart`, `dataEnd` and `alignWeekday` you give `resolveComparison`, and the comparison shows the dates the app will fetch, or “Not enough history” or “Nothing to compare” when the data can’t cover them. Here sales data runs to today, so this month compares with the same days of last month, and the previous year lines up weekdays.

```tsx-live
<DashboardPeriod
  today='2026-10-07'
  dataEnd='2026-10-07'
  alignWeekday
  defaultValue={{ range: 'this-month', compare: 'previous-period' }}
/>
```

### With your own controls

The comparison is dates only. A benchmark that isn’t a date, such as similar venues, is the app’s own control: pass it as `children` and it sits after the period.

```tsx-live
<DashboardPeriod defaultValue={{ range: 'last-month', compare: 'previous-period' }}>
  <Select defaultValue='similar-venues'>
    <Select.Trigger aria-label='Benchmark' className='w-full @sm:w-fit gap-2'>
      <Select.Value />
      <Select.Icon />
    </Select.Trigger>
    <Select.Content>
      <Select.Item value='similar-venues'>Similar venues</Select.Item>
      <Select.Item value='similar-shows'>Similar shows</Select.Item>
    </Select.Content>
  </Select>
</DashboardPeriod>
```

### In a dashboard

Give a dashboard description a `period`, and [DashboardView](/charts/dashboards#periods-and-comparisons) shows this toolbar above its sections. Its `onPeriodChange` gets the new period: resolve it with `resolveDateRange` and `resolveComparison`, fetch, and pass back a description with the new `period` and its `history`. A delta marked `comparison: true` follows the comparison. Here sales data starts on 1 March 2026, so month to date has nothing to compare with a year back. Choose the previous period to see the deltas.

```tsx-live-noinline
// Wed 7 Oct 2026 in Melbourne. Sales data runs from 1 March to today.
const TODAY = '2026-10-07'
const SALES_DATA = {
  now: new Date('2026-10-07T02:00:00Z'),
  timeZone: 'Australia/Melbourne',
  dataStart: '2026-03-01',
  dataEnd: TODAY
}

function historyOf({ range, compare }) {
  if (!compare) return undefined
  const { status } = resolveComparison(range, compare, SALES_DATA)
  return status === 'available' ? undefined : status
}

function Sales() {
  const [period, setPeriod] = useState({ range: { period: 'month', offset: 0, toDate: true }, compare: 'previous-year' })
  const history = historyOf(period)
  const spec = {
    version: 1,
    title: 'Sales',
    period: history ? { ...period, history } : period,
    sections: [
      {
        title: 'At a glance',
        cards: [
          { id: 'sold', kind: 'stat', size: 'stat', label: 'Tickets sold', value: 2531, delta: { value: 0.04, format: 'percent', comparison: true } },
          { id: 'gross', kind: 'stat', size: 'stat', label: 'Gross revenue', value: 118400, format: 'compactCurrency', delta: { value: -0.06, format: 'percent', comparison: true } },
          { id: 'orders', kind: 'stat', size: 'stat', label: 'Orders', value: 1288, delta: { value: 96, comparison: true } },
          { id: 'through', kind: 'stat', size: 'stat', label: 'Sell-through', value: 0.77, format: 'percent', delta: { value: 9, format: 'points' }, context: 'Target is 85%' }
        ]
      }
    ]
  }
  return (
    <DashboardView
      spec={spec}
      onPeriodChange={setPeriod}
      periodProps={{
        presets: dateRangePresets,
        today: TODAY,
        timeZone: SALES_DATA.timeZone,
        dataStart: SALES_DATA.dataStart,
        dataEnd: SALES_DATA.dataEnd
      }}
    />
  )
}

render(<Sales />)
```

## Guidelines

- **Previous period follows the calendar.** This month compares with last month, this quarter with last quarter, and month to date with last month to the same day. Rolling and custom ranges compare with the same number of days, ending the day before.
- **Say when there’s nothing to compare.** Pass `dataStart` to `resolveComparison` and to this toolbar. When the comparison starts before the data, the cards say “Not enough history”; when it ends before, “Nothing to compare”. Neither shows a delta.
- **Keep the period in the description.** The toolbar shows the description’s `period`, so cards and controls never disagree.

<div className='grid gap-8'>

<Guideline title='Compare like with like'>
  <Guideline.Do code={`resolveComparison(range, compare, { now, timeZone, dataEnd: today })`}>
    Pass `dataEnd` for data recorded as it happens, such as sales. A period still in progress then compares with the same days of the period before. Leave it out for dates known ahead, such as shows coming up.
  </Guideline.Do>
  <Guideline.Dont code={`resolveComparison('this-month', 'previous-period', { now, timeZone })`}>
    Don’t compare a month that’s two days old with a whole month. The delta looks like a fall.
  </Guideline.Dont>
</Guideline>

<Guideline title='Dates only'>
  <Guideline.Do>
    Put a benchmark such as similar venues in its own control, beside the period.
  </Guideline.Do>
  <Guideline.Dont>
    Don’t add benchmarks to the comparison choices. A comparison is always another date range.
  </Guideline.Dont>
</Guideline>

## Accessibility

- The toolbar is a group named “Dashboard period”, or by your `aria-label`.
- The button is named after its period and comparison, such as “Choose dates, Period (This month, 1 to 31 Oct 2026, vs 1 to 30 Sept 2026)”. It works as [DateRangePicker](/components/date-range-picker) does with `commit='apply'`: Cancel, `Escape` or the drawer’s Close drops changes to both the period and the comparison.
- After the range comes the Compare [Switch](/components/switch), then a [ToggleGroup](/components/toggle-group) named “Compare with”, then the comparison’s dates, which are announced as they change. On a phone the Compare row sits above Clear and Apply at the drawer’s foot, so it stays in view on both tabs.
- Read only, the button shows a lock and doesn’t open.
