A dashboard’s period and what it compares with, in one picker.

## Import

```tsx
import { DashboardPeriod } from '@oztix/roadie-components/dashboard-period'
```

## Examples

### Default

One button shows the period and, when there is one, the dates it compares with: “This month 1 to 31 Oct 2026 vs 1 to 30 Sept 2026”. It opens a [DateRangePicker](/components/date-range-picker) that waits for Apply, because each change refetches every card. Its presets look ahead 30 and 90 days, back 30 days and 12 months, and over this financial year. Under the range, the Compare switch turns the comparison on, and Previous period or Previous year picks it, with the dates it covers below. Apply sends the period and its comparison together. The value is `{ range, compare }`, and no comparison leaves `compare` out. `compareOptions` changes the choices: see below.

```tsx-live-noinline
function Default() {
  const [period, setPeriod] = useState({ range: 'this-month', compare: 'previous-period' })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod value={period} onValueChange={setPeriod} />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Default />)
```

### States

`readOnly` shows the period and comparison with a lock, for a dashboard whose period the page sets, such as one show’s on-sale window. `disabled` turns it off.

```tsx-live
<div className='grid gap-4'>
  <div className='grid gap-1'>
    <p className='text-sm text-subtle'>Default</p>
    <DashboardPeriod defaultValue={{ range: 'last-month', compare: 'previous-period' }} />
  </div>
  <div className='grid gap-1'>
    <p className='text-sm text-subtle'>Read only</p>
    <DashboardPeriod readOnly defaultValue={{ range: { start: '2026-11-02', end: '2026-11-29' }, compare: 'previous-year' }} />
  </div>
  <div className='grid gap-1'>
    <p className='text-sm text-subtle'>Disabled</p>
    <DashboardPeriod disabled defaultValue={{ range: 'last-month', compare: 'previous-period' }} />
  </div>
</div>
```

### With custom dates

Add `'custom'` to `compareOptions`, and Custom dates opens a range of its own, starting from the previous period’s dates. The comparison is then `{ start, end }`. Leave it out, as by default, and custom dates the app sets still show as Custom dates, without a picker, so switching away and back keeps them.

```tsx-live-noinline
function Custom() {
  const [period, setPeriod] = useState({
    range: { start: '2026-11-02', end: '2026-11-08' },
    compare: { start: '2025-11-03', end: '2025-11-09' }
  })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod
        today='2026-10-07'
        value={period}
        onValueChange={setPeriod}
        compareOptions={['none', 'previous-period', 'previous-year', 'custom']}
      />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Custom />)
```

### With your own comparisons

`compareOptions` lists the choices in order. Roadie’s are `'previous-period'`, `'previous-year'` and `'custom'`. The app’s own are `{ value, label, description? }`, such as similar venues. Choosing one sets `compare` to its `value`, which comes back as it is: Roadie works out no dates for it, shows its `description` where the dates go, and the button reads “vs similar venues”. `'none'` adds the Compare switch. Leave it out, as here, and nothing turns the comparison off once one is chosen. The default is `['none', 'previous-period', 'previous-year']`. A comparison the value holds that the list leaves out still shows among the choices. If you hoist the list, add `as const`, so TypeScript keeps your values.

```tsx-live-noinline
function Benchmark() {
  const [period, setPeriod] = useState({ range: 'last-month', compare: 'similar' })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod
        today='2026-10-07'
        value={period}
        onValueChange={setPeriod}
        compareOptions={[
          'previous-period',
          'previous-year',
          'custom',
          { value: 'similar', label: 'Similar venues', description: 'Venues of a like size in Melbourne' }
        ]}
      />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Benchmark />)
```

### With presets

`presets` replaces the period’s list, as on DateRangePicker. A sales dashboard reports on periods to date, so it takes the picker’s own `dateRangePresets`.

```tsx-live
<DashboardPeriod
  defaultValue={{ range: { period: 'month', offset: 0, toDate: true }, compare: 'previous-period' }}
  presets={dateRangePresets}
/>
```

### With fixed presets

A preset can be fixed dates, such as a last 30 days that ends yesterday, worked out by the app. When the period is one of them, the button shows its label with its dates, as it does for relative presets, and the phone’s list shows its dates beside it.

```tsx-live-noinline
// Wed 7 Oct 2026. The app's data ends yesterday.
const PRESETS = [
  { value: { direction: 'next', amount: 30, unit: 'day' } },
  { value: { start: '2026-09-07', end: '2026-10-06' }, label: 'Last 30 days' },
  { value: { start: '2025-10-07', end: '2026-10-06' }, label: 'Last 12 months' },
  { value: { start: '2026-07-01', end: '2027-06-30' }, label: 'This financial year' }
]

function Fixed() {
  const [period, setPeriod] = useState({
    range: { start: '2026-09-07', end: '2026-10-06' },
    compare: 'previous-period'
  })
  return (
    <div className='grid gap-4'>
      <DashboardPeriod today='2026-10-07' presets={PRESETS} value={period} onValueChange={setPeriod} />
      <p className='text-sm text-subtle'>Value: {JSON.stringify(period)}</p>
    </div>
  )
}

render(<Fixed />)
```

### With the data’s dates

Pass the same `dataStart`, `dataEnd` and `alignWeekday` you give `resolveComparison`, and the comparison shows the dates the app will fetch, or “Not enough history” or “Nothing to compare” when the data can’t cover them. Here sales data runs to today, so this month compares with the same days of last month, and the previous year lines up weekdays.

```tsx-live
<DashboardPeriod
  today='2026-10-07'
  dataEnd='2026-10-07'
  alignWeekday
  defaultValue={{ range: 'this-month', compare: 'previous-period' }}
/>
```

### With your own controls

Pass the app’s other controls, such as a channel filter, as `children`, and they sit after the period. On a narrow container they stack.

### In a dashboard

Give a dashboard description a `period`, and [DashboardView](/charts/dashboards#periods-and-comparisons) shows this toolbar above its sections. Its `onPeriodChange` gets the new period: resolve it with `resolveDateRange` and `resolveComparison`, fetch, and pass back a description with the new `period` and its `history`. A delta marked `comparison: true` follows the comparison. Here sales data starts on 1 March 2026, so month to date has nothing to compare with a year back. Choose the previous period to see the deltas.

```tsx-live-noinline
// Wed 7 Oct 2026 in Melbourne. Sales data runs from 1 March to today.
const TODAY = '2026-10-07'
const SALES_DATA = {
  now: new Date('2026-10-07T02:00:00Z'),
  timeZone: 'Australia/Melbourne',
  dataStart: '2026-03-01',
  dataEnd: TODAY
}

function historyOf({ range, compare }) {
  if (!compare) return undefined
  const { status } = resolveComparison(range, compare, SALES_DATA)
  return status === 'available' ? undefined : status
}

function Sales() {
  const [period, setPeriod] = useState({ range: { period: 'month', offset: 0, toDate: true }, compare: 'previous-year' })
  const history = historyOf(period)
  const spec = {
    version: 1,
    title: 'Sales',
    period: history ? { ...period, history } : period,
    sections: [
      {
        title: 'At a glance',
        cards: [
          { id: 'sold', kind: 'stat', size: 'stat', label: 'Tickets sold', value: 2531, delta: { value: 0.04, format: 'percent', comparison: true } },
          { id: 'gross', kind: 'stat', size: 'stat', label: 'Gross revenue', value: 118400, format: 'compactCurrency', delta: { value: -0.06, format: 'percent', comparison: true } },
          { id: 'orders', kind: 'stat', size: 'stat', label: 'Orders', value: 1288, delta: { value: 96, comparison: true } },
          { id: 'through', kind: 'stat', size: 'stat', label: 'Sell-through', value: 0.77, format: 'percent', delta: { value: 9, format: 'points' }, context: 'Target is 85%' }
        ]
      }
    ]
  }
  return (
    <DashboardView
      spec={spec}
      onPeriodChange={setPeriod}
      periodProps={{
        presets: dateRangePresets,
        today: TODAY,
        timeZone: SALES_DATA.timeZone,
        dataStart: SALES_DATA.dataStart,
        dataEnd: SALES_DATA.dataEnd
      }}
    />
  )
}

render(<Sales />)
```

## Guidelines

- **Previous period follows the calendar.** This month compares with last month, this quarter with last quarter, and month to date with last month to the same day. Rolling ranges, fixed dates and custom comparisons compare with the same number of days, ending the day before.
- **A period to date compares with the same days a period back.** On 7 Oct 2026, this financial year to date, or this financial year with `dataEnd` set to today, compares with 1 Jul to 7 Oct 2025, last financial year to the same day. The same year as fixed dates, `{ start: '2026-07-01', end: '2027-06-30' }` with `dataEnd` set to yesterday, compares with the same number of days just before it instead: 25 Mar to 30 Jun 2026. Pick the form that matches how your data is compared.
- **Give your own comparisons values of their own.** Not `'none'`, `'custom'`, `'previous-period'` or `'previous-year'`: an option with one of those values is left out, with a warning in development. Roadie treats any other `compare` as no comparison of its own: `resolveComparison` refuses it, `DashboardView` hides deltas marked `comparison: true`, and `validateDashboard` warns about them, and about one that reads like Roadie’s, such as `'previous_period'`.
- **Say when there’s nothing to compare.** Pass `dataStart` to `resolveComparison` and to this toolbar. When the comparison starts before the data, the cards say “Not enough history”; when it ends before, “Nothing to compare”. Neither shows a delta.
- **One size, paired with large controls.** The button is a large control: 48px tall, with the comparison's dates on a second line. On the same row, use `size='lg'` Buttons, IconButtons and Selects.
- **Keep the period in the description.** The toolbar shows the description’s `period`, so cards and controls never disagree.

## Accessibility

- The toolbar is a group named “Dashboard period”, or by your `aria-label`.
- The button is named after its period and comparison, such as “Choose dates, Period (This month, 1 to 31 Oct 2026, vs 1 to 30 Sept 2026)”. It works as [DateRangePicker](/components/date-range-picker) does with `commit='apply'`: Cancel, `Escape` or the drawer’s Close drops changes to both the period and the comparison.
- After the range comes the Compare [Switch](/components/switch), when `compareOptions` has `'none'`, then a [ToggleGroup](/components/toggle-group) named “Compare with”, then the comparison’s dates or your option’s description, which are announced as they change. On a phone the Compare row sits above Apply at the drawer’s foot, so it stays in view on both tabs, and the choices wrap onto a second row when they don’t fit.
- With Custom dates, a [DateRangePicker](/components/date-range-picker) named “Comparison dates” sits under the choices. It opens over the picker, a drawer over the drawer on a phone, and its dates wait for Apply with the rest.
- Read only, the button shows a lock and doesn’t open.
